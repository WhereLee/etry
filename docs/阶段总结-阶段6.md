# 阶段6总结：运营端（资料管理 / 权限点矩阵 / RBAC / 审计 / 退款申请 / 财务导出）

## 一、本阶段做了什么

### 功能清单
- **资料管理（运营）**：`/api/admin/materials` 全生命周期——新建（默认下架、默认不推荐）、编辑（改价/分类/学段/学科/页数/试读页数，保持上架态）、上传 PDF（仅 PDF 魔数校验，fileKey 规范 `material/upload-{id}-*`）、上下架（守卫：上架前必须已挂文件且价格>0）、首页推荐位开关。管理端列表支持关键词/分类/上架状态筛选与分页。
- **权限点矩阵**：12 个权限点（material:* / order:read / order:operate / refund:operate / recon:* / user:read / user:manage / audit:read）经 `@PreAuthorize("hasAuthority('perm:code')")` 落到每个管理端接口；5 个内置角色（BUYER/OPERATOR/CUSTOMER_SERVICE/FINANCE/SUPER_ADMIN）按职责授角。JwtAuthFilter 每请求从库读角色+权限点，授角即时生效（同 token 无需重登）。
- **RBAC 角色管理**：`GET /api/admin/roles`（角色目录含权限点）、`GET/PUT /api/admin/users/{id}/roles`（查看/调整用户角色）。自守卫禁止改自己角色、未知角色 400、用户不存在 404、空列表清空角色；调整写审计 `USER_ROLES_ASSIGN`。
- **审计日志**：`@AdminAudit` 注解 + AOP 切面记录管理端动作（含失败尝试 success=0、errorMessage 截断 500、耗时、traceId）；`GET /api/admin/audit-logs` 按操作人/动作/目标类型/结果筛选分页（audit:read）。
- **客服权益视图**：`GET /api/admin/users/{id}/entitlements` 查买家已购权益（user:read），客服可核对发放/回收。
- **买家退款申请 + 客服处理**：买家 `POST/GET /api/orders/{orderNo}/refund-request`（限流 5/60s，仅 PAID/FULFILLED/REFUND_FAILED 可申请，一单一申请 UNIQUE，拒绝后可再次申请）；客服/财务 `GET /api/admin/refund-requests` + `POST /{id}/approve|reject`。同意=条件抢占后复用退款内核 `RefundService.refund` 整单原路退款并回收权益，失败回滚抢占；拒绝带备注展示给买家。
- **财务导出**：订单导出 `GET /api/admin/orders/export`、对账差异导出 `GET /api/admin/reconciliation/runs/{id}/breaks/export`（EasyExcel xlsx，recon:read）。
- **前端**：资料管理页（CRUD/上传/上下架/推荐位开关）、用户角色对话框（5 角色+权限点数）、审计日志页（筛选+动作中文映射）、系统配置页（只读 RBAC 权限点×角色矩阵）、订单页退款申请对话框（待处理/已同意/已拒绝分页签，同意/拒绝）、买家订单详情退款申请对话框与申请状态条（已拒绝展示备注+可再次申请）。

### 技术要点
- 退款申请并发安全：`UPDATE ... WHERE id=? AND status='PENDING'` 条件抢占，命中才退款，异常 `revertToPending` 回滚——6 并发同意恰好退款一次。
- 退款内核零改动：退款申请仅做「申请-审核」编排，资金动作完全复用既有 `RefundService.refund`，不新增资金语义。
- 审计切面记录失败尝试：上下架守卫拦截等失败动作也落库（success=0），便于运营追溯误操作。
- 架构守卫：ArchUnit 模块边界（operations.admin 仅经 commerce.api facade）+ 表归属（t_refund_request→commerce）+ 跨模块读模型豁免登记（RefundRequestRepository→t_user）。
- 模块边界：RBAC 管理落 identity 模块，退款申请落 commerce 模块并经 api facade 暴露给 operations.admin。

## 四、当前阶段的已知缺陷
- 前端控制台 UI 仍按 legacy session.role（ADMIN/TEACHER/STUDENT）门禁，纯 RBAC 身份（如仅授 CUSTOMER_SERVICE 而无 legacy ADMIN）看到的是学员布局；接口权限矩阵已由集成测试逐身份验证，UI 角色门禁与 RBAC 的彻底统一留待后续。
- 旧课程控制器（AdminSeriesController、TeacherInvitationAdminController）仍用 @RequireRole，待课程域退役决策后统一迁移到权限点。
- 真实支付宝仍为 mock，待商户号（沙箱即可）接入后做 ¥0.01 真实支付验收（阶段7）。
- 导出为同步全量 EasyExcel，超大数据量需分页流式；当前演示规模无压力。
