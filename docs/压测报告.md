# btry k6 压测报告

更新日期：2026-11-05

## 1. 环境与方法

- 云服务器：3.7GB 内存，生产 systemd、staging、observability 同时运行
- k6：`grafana/k6:0.54.0`，Docker `--network host`
- 目标：`http://127.0.0.1:18080`（nginx → backend）
- 视频仍由浏览器直连 COS，压测不下载视频字节，只测播放地址预签名/缓存
- k6 与应用在同一台主机，存在 CPU 竞争，结论按方向性使用

## 2. 场景

| 场景 | 并发 | 时长 | 说明 |
|---|---:|---:|---|
| browse | ramp 到 100 VU | 4 分钟 | 系列列表 + 系列详情，无写操作 |
| playback_control | 5 VU | 3 分钟 | 播放地址获取，间隔 3s，避免触发 120/min 限流 |
| order_write | 5 VU × 1 次 | 约 1 秒 | 创建订单、Mock 支付、模拟回调 |
| order_read | 20 VU | 3 分钟 | 订单详情 |

最大 VU：130。登录只在 setup 执行一次；订单写使用 10 个隔离 LOAD 系列。

## 3. 结果

整体：

- 请求：75,271
- 失败：0（0.00%）
- checks：75,271 / 75,271 通过
- 吞吐：约 312.55 req/s
- 迭代：41,345
- 总耗时：约 4 分钟

延迟：

| 场景 | p95 | max |
|---|---:|---:|
| browse | 6.10ms | 38.82ms |
| playback_control | 9.35ms | 12.73ms |
| order_read | 8.04ms | 58.50ms |
| order_write | 54.25ms | 59.49ms |
| 整体 | 6.36ms | 87.12ms |

服务端：

- Hikari 峰值 active：3
- Hikari 峰值 pending：0
- MySQL Slow_queries：0
- MySQL Threads_connected（压测后）：11
- GC 最大暂停：约 10ms
- Full GC：0
- 压测后堆使用：约 93MB / 140MB（最大堆约 360MB）

## 4. 容量结论

在本次测试的 130 VU 组合（100 browse + 20 order read + 5 playback + 5 order write）下，后端控制面没有打满：

- 错误率为 0；
- 读接口 p95 低于 10ms；
- 订单写 p95 约 54ms；
- Hikari 没有等待；
- 没有 Full GC 或 OOM。

因此目前没有数据支持扩大连接池或修改 JVM 参数。100 个并发浏览/控制面请求在该 staging 主机上已被验证为稳定；这不等于 100 个视频流经过服务器，视频字节仍然直连 COS。

下一步如果继续压测，建议用独立压测机复测 200/300 VU，并重点观察：

- Hikari pending 是否开始大于 0；
- MySQL CPU 和连接数；
- GC 暂停是否上升；
- nginx/后端 CPU 是否成为瓶颈。

## 5. 复现

```bash
# 1. 导入隔离 LOAD 系列（仅 staging）
docker compose exec -T mysql mysql -uroot btry_staging < tools/k6/seed-load-series.sql

# 2. smoke
docker run --rm -u 0 --network host \
  -v /home/ubuntu/btry-staging/tools/k6:/scripts \
  -e BASE_URL=http://127.0.0.1:18080 \
  -e STUDENT_PASSWORD="$STUDENT_PASSWORD" \
  grafana/k6:0.54.0 run /scripts/smoke.js

# 3. 完整阶梯
docker run --rm -u 0 --network host \
  -v /home/ubuntu/btry-staging/tools/k6:/scripts \
  -e BASE_URL=http://127.0.0.1:18080 \
  -e STUDENT_PASSWORD="$STUDENT_PASSWORD" \
  grafana/k6:0.54.0 run --summary-export /scripts/load-summary.json /scripts/load.js

# 4. 清理测试数据
docker compose exec -T mysql mysql -uroot btry_staging < tools/k6/cleanup-load-data.sql
```

## 6. 限制

- 压测机与应用同主机，CPU、磁盘和网络会互相影响；
- 未覆盖真实支付宝网关、真实 COS 大文件下载和 40 分钟长视频；
- 订单写受每用户 20/min 限流，5 VU 是功能性验证，不代表写吞吐上限；
- 真实生产并发要以独立压测机和线上监控复测为准。
