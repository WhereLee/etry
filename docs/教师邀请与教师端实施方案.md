# 教师邀请与教师端实施方案

更新日期：2026-11-02

状态：**批次 A 已实现（2026-11-02）**

## 1. 批次目标

完成教师端的第一个可用闭环：

- 管理员生成一次性教师邀请链接；
- 教师通过邀请链接自行设置密码并激活账号；
- 教师登录后进入教师工作台；
- 教师只能看到自己的系列；
- 后端强制校验教师资源归属；
- 管理员仍可查看全部系列和账号。

本批次不包含：

- 系列、章节、视频编辑；
- 视频上传；
- 发布/下架状态；
- 学习进度；
- 收费。

## 2. 账号规则

| 角色 | 账号来源 | 密码来源 |
|---|---|---|
| 管理员 | 初始化或受控运维创建 | 管理员自行修改 |
| 学员 | 管理员创建 | 初始密码 + 首次登录强制修改 |
| 教师 | 管理员发送一次性邀请，教师激活 | 教师激活时自行设置 |

教师邀请不是公开注册：

- 管理员必须先创建邀请；
- 邀请绑定用户名和昵称；
- 邀请只创建 `TEACHER`；
- 一个邀请只能成功使用一次；
- 默认 72 小时过期；
- 管理员可以撤销未使用的邀请。

## 3. 数据模型

### 3.1 新表 `t_teacher_invitation`

```sql
CREATE TABLE t_teacher_invitation
(
    id          BIGINT       NOT NULL AUTO_INCREMENT,
    token_hash  CHAR(64)     NOT NULL,
    username    VARCHAR(20)  NOT NULL,
    nickname    VARCHAR(50)  NOT NULL,
    status      VARCHAR(20)  NOT NULL DEFAULT 'PENDING',
    expires_at  DATETIME(3)  NOT NULL,
    created_by  BIGINT       NOT NULL,
    used_by     BIGINT       NULL,
    created_at  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    used_at     DATETIME(3)  NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_teacher_invitation_token (token_hash),
    KEY idx_teacher_invitation_status (status, expires_at),
    KEY idx_teacher_invitation_creator (created_by, created_at),
    KEY idx_teacher_invitation_username (username, status)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT ='教师邀请';
```

状态：

- `PENDING`：待使用。
- `USED`：已成功激活。
- `REVOKED`：管理员撤销。

过期不额外改状态，展示时通过 `expires_at` 计算；定时清理任务后续再做。

### 3.2 用户创建复用

将“创建用户”的数据库写入抽到用户仓储或统一账号写入服务，供两处复用：

- 管理员创建学员；
- 教师邀请激活。

教师邀请激活时：

- `role = TEACHER`；
- `status = ACTIVE`；
- `must_change_password = 0`，因为密码由教师本人设置；
- `token_version = 0`。

## 4. 邀请 token 设计

- 使用 `SecureRandom` 生成 32 字节随机值。
- 使用 Base64 URL-safe 编码生成链接 token。
- 数据库只保存 SHA-256 十六进制哈希。
- 明文 token 只在创建成功时返回一次，供管理员复制链接。
- 日志、审计和异常信息禁止记录明文 token。
- 邀请链接示例：`https://域名/invite/<token>`。
- 前端页面不把 token 写入额外日志或埋点。

## 5. 后端接口

### 5.1 管理员接口

均要求 `ADMIN` 角色。

#### 创建邀请

```http
POST /api/admin/teacher-invitations
```

请求：

```json
{
  "username": "physics_teacher",
  "nickname": "物理老师"
}
```

响应：

```json
{
  "id": 1,
  "username": "physics_teacher",
  "nickname": "物理老师",
  "inviteUrl": "https://example.com/invite/plain-token",
  "expiresAt": "2026-11-05T10:00:00"
}
```

规则：

- 用户名必须符合现有 4-20 位字母、数字、下划线规则；
- 用户名已存在时拒绝；
- 同一用户名已有未过期 `PENDING` 邀请时拒绝；
- 使用 `@RateLimit`、`@Idempotent`、`@Measured`、`@AdminAudit`；
- 审计目标类型为 `TEACHER_INVITATION`，目标 ID 从返回值获取。

#### 邀请列表

```http
GET /api/admin/teacher-invitations?status=PENDING&page=1&size=20
```

返回用户名、昵称、状态、创建人、创建时间、过期时间和使用时间；过期状态由后端计算。

明文 token 不返回。列表页面只允许“复制邀请链接”在创建成功时进行；已存在的邀请无法再次获取明文链接，只能撤销后重新生成。

#### 撤销邀请

```http
PUT /api/admin/teacher-invitations/{id}/revoke
```

规则：

- 只有 `PENDING` 且未过期的邀请可以撤销；
- 已使用或已撤销的邀请不重复处理；
- 写入管理员审计。

### 5.2 公开邀请接口

这两个接口不需要登录，但必须进行 IP 限流。

#### 校验邀请

```http
POST /api/auth/teacher-invitations/preview
```

请求：

```json
{ "token": "plain-token" }
```

响应只返回绑定的用户名、昵称和过期时间，不返回创建人、数据库 ID 等内部信息。

失败统一返回“邀请无效或已过期”，避免区分具体状态造成信息泄露。

#### 接受邀请

```http
POST /api/auth/teacher-invitations/accept
```

请求：

```json
{
  "token": "plain-token",
  "password": "Teacher1234",
  "confirmPassword": "Teacher1234"
}
```

规则：

- 密码继续使用后端 `@StrongPassword`；
- 前后端都校验两次密码一致；
- 接受成功后不自动登录，返回成功并跳转登录页；
- 同一邀请并发提交只能成功一次。

## 6. 邀请接受事务

1. 计算 token 哈希。
2. 使用 `SELECT ... FOR UPDATE` 查询邀请。
3. 校验 `PENDING` 和 `expires_at`。
4. 再次检查用户名是否已被占用。
5. 创建 `TEACHER` 用户。
6. 条件更新邀请为 `USED`，写入 `used_by`、`used_at`。
7. 提交事务。

任何一步失败整体回滚。数据库唯一约束作为最后防线：

- `t_user.username` 唯一；
- `t_teacher_invitation.token_hash` 唯一。

## 7. 安全控制

- 公开邀请接口按 IP 限流，例如 10 分钟最多 20 次。
- 管理员创建邀请接口按管理员限流。
- `JwtAuthFilter` 只放行邀请预览和接受两个公开路径。
- 不使用 `X-Forwarded-For`，除非可信代理配置已开启。
- 邀请接受成功后，token 立即失效。
- 明文 token 不进入数据库、日志和审计。
- 响应头和前端继续使用 `Referrer-Policy: no-referrer`。
- 邀请只创建 `TEACHER`，请求体不接收角色字段。
- 被撤销、过期、已使用的邀请统一返回不可用。

## 8. 教师端接口

### 8.1 我的系列

```http
GET /api/teacher/series
```

要求 `TEACHER` 角色，返回当前 `teacher_id` 拥有的系列：

- 系列 ID；
- 标题；
- 简介；
- 章节数量；
- 视频数量；
- 更新时间。

### 8.2 我的系列详情

```http
GET /api/teacher/series/{id}
```

规则：

- 只能访问 `teacher_id = 当前登录用户 ID` 的系列；
- 他人系列返回 `404`，不泄露是否存在；
- 管理员不通过教师接口管理内容，继续使用管理员接口。

## 12. 测试计划

### 12.1 邀请服务

- 创建邀请只保存哈希，不保存明文 token；
- 同一用户名已有有效邀请时拒绝重复创建；
- 邀请过期后不能预览或接受；
- 撤销后不能使用；
- 已使用邀请不能再次使用；
- 接受邀请只能创建 `TEACHER`；
- 接受成功后密码可登录，且不要求再次改密；
- 弱密码被拒绝；
- 并发接受同一邀请只有一个成功；
- 账号创建失败时邀请仍保持 `PENDING`。

### 12.2 接口权限

- 未登录访问管理员邀请接口返回 `401`；
- 教师和学员访问管理员邀请接口返回 `403`；
- 匿名用户只能访问预览和接受接口；
- 教师访问管理员用户接口返回 `403`；
- 教师访问他人系列详情返回 `404`。

### 12.3 前端

- 管理员创建邀请并复制链接；
- 教师打开邀请链接完成激活；
- 无效/过期/已使用邀请展示统一错误；
- 教师登录后进入 `/teacher/series`；
- 学员不会进入教师页面；
- 管理员导航包含教师邀请；
- `npm run build` 通过；
- 浏览器控制台无错误。

## 13. 验收标准

- 管理员能生成、复制、查看和撤销教师邀请。
- 邀请链接一次性、限时、不可伪造。
- 教师能通过邀请设置密码并激活账号。
- 教师激活后只能进入教师工作台。
- 教师只能看到自己的系列，访问他人系列被后端拒绝。
- 教师不能访问管理员账号和系列分配接口。
- 学员仍由管理员建号，学习空间行为不受影响。
- 后端测试、前端构建和浏览器验收通过。
