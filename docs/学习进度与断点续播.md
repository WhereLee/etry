# 学习进度与断点续播

更新日期：2026-11-02

状态：**批次 D 已实现**

## 1. 目标

为学员提供最小学习连续性：

- 记录每个视频最后播放位置；
- 再次进入系列时自动定位到最近未完成视频；
- 视频切换时恢复各自断点；
- 展示系列完成度；
- 播放完成后标记已看。

不引入积分、排行榜、打卡和复杂学习计划。

## 2. 数据模型

`t_learning_progress`：

- `user_id`；
- `series_id`；
- `video_id`；
- `position_seconds`；
- `duration_seconds`；
- `completed`；
- `created_at` / `updated_at`。

唯一约束：`(user_id, video_id)`。

## 3. 保存规则

- 播放中每约 10 秒保存一次；
- 暂停、拖动结束、URL 刷新前保存；
- 页面离开时使用 keepalive 请求保存；
- 播放结束或位置达到视频 95% 时标记完成；
- `completed` 一旦为 true，不会因为回看而取消；
- 完成时位置归一到视频末尾；
- 保存失败不影响播放主链路。

## 4. 权限

进度接口要求 `STUDENT` 角色，并校验：

- 视频存在；
- 系列已发布；
- 学员已被分配该系列。

管理员和教师不能通过学员进度接口写入学习记录。

## 5. 接口

```http
PUT /api/learning/videos/{videoId}/progress
```

请求：

```json
{
  "positionSeconds": 75,
  "durationSeconds": 181,
  "completed": false
}
```

## 6. 前端行为

- 学习空间卡片显示“已完成 x / y”和进度条；
- 系列详情显示每节视频的完成状态或观看百分比；
- 进入系列时优先选择第一个“未完成且已有进度”的视频；
- 播放器在 `loadedmetadata` 后恢复对应位置；
- 切换到已完成视频时从头播放。

## 7. 验收

- 保存 30 秒后重新进入系列，播放器定位到约 30 秒；
- 视频列表显示观看百分比；
- 播放完成后显示“已完成”；
- 学习空间完成数增加；
- 归档或未分配视频不能写进度；
- 教师调用进度接口返回 `403`。
