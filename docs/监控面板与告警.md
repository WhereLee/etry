# 监控面板与告警

更新日期：2026-11-05

## 1. 组件与端口

可选 `compose.observability.yml`：

- Prometheus：`127.0.0.1:19090`
- Grafana：`127.0.0.1:13000`
- Jaeger UI：`127.0.0.1:16686`
- Jaeger OTLP HTTP：`127.0.0.1:14318`

全部只绑定回环，不暴露公网；默认不启动，避免长期占用 staging 内存。

## 2. 启动与停止

```bash
cd /home/ubuntu/btry-staging

sudo docker compose --env-file .env.docker \
  -f compose.yml -f compose.observability.yml \
  --profile observability up -d prometheus grafana jaeger

sudo docker compose --env-file .env.docker \
  -f compose.yml -f compose.observability.yml \
  --profile observability stop prometheus grafana jaeger
```

Grafana 管理员密码来自 `.env.docker` 的 `GRAFANA_ADMIN_PASSWORD`，不写入仓库。

## 3. 面板

预置 dashboard：`btry overview`，通过 provisioning 自动加载。

面板包括：

- Backend Up
- JVM Heap
- JVM GC Pause
- HTTP Requests / 5xx
- HTTP Latency p95/p99
- Hikari Connections（active/idle/pending）
- JVM Threads
- Payment Counters（提交、支付、履约）
- Playback Cache / Queue

## 4. 指标配置

`application.yml` 已开启 HTTP 分位桶：

```yaml
management:
  metrics:
    distribution:
      percentiles-histogram:
        http.server.requests: true
      percentiles:
        http.server.requests: 0.5,0.95,0.99
```

因此 Prometheus 可以查询 `http_server_requests_seconds_bucket` 并计算 p95/p99。

## 5. 验证结果

- Prometheus target `up{job="btry-backend"}` = 1
- Grafana `/api/health` 返回 `database: ok`
- Grafana dashboard search 返回 `btry overview`
- Jaeger services 包含 `btry-learning-space`
- JVM、Hikari、HTTP、支付指标均能从 Prometheus 查询

## 6. 告警边界

当前不引入 Alertmanager，原因是没有真实 on-call 和 webhook 流程。业务告警继续走应用内 `AlertPublisher`：

- 支付金额不一致
- 已支付未履约
- 支付中堆积
- 退款重试耗尽
- 订单履约失败

后续有真实告警渠道时，再增加 Prometheus 规则和 Alertmanager；不要只为了“有告警”堆一个没有人接收的组件。

## 7. 资源

本次验证时观测栈大致占用：

- Grafana：约 51 MiB / 256 MiB
- Prometheus：约 22 MiB / 320 MiB
- Jaeger：约 84 MiB / 192 MiB

观测栈与 staging、生产同时运行会增加 swap 使用；压测和排查结束后应停止观测栈。
