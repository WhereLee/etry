# 资金对账与按支付尝试退款

## 资金分层

- `t_order`：业务订单和权益来源，最多驱动一次课程权益发放。
- `t_payment_attempt`：一次具体收银台支付尝试，保存商户单号和渠道交易号。
- `t_payment_event`：已验签渠道事件，按 attempt 落账，是支付审计事实。
- `t_refund`：按支付尝试退款。`ORDER` 退主支付并撤销权益；`DUPLICATE_PAYMENT` 只退第二笔资金。

## 成功与失败

- 验签成功的 `PAYMENT_SUCCESS` 必须带渠道交易号和匹配的商户单号。
- 成功事件永远落到自身 attempt，不按“最新 attempt”猜归属。
- `PAYING` 或当前 attempt 的 `PAY_FAILED` 收到成功时，订单恢复/进入 `PAID`。
- 已支付订单收到不同渠道交易号的成功事件，标记 repeat payment 并告警，不重复发权益。
- 迟到失败只影响自身 attempt；只有当前 attempt 的失败可推动 `PAYING -> PAY_FAILED`。

## 主动对账

补偿任务以 attempt 为单位查询 `PROCESSING/SUPERSEDED`，通过 `next_reconcile_at` 做数据库租约，避免多实例重复调用。

- 订单已完成但旧收银台实际付款：查单发现 `PAID`，记录第二笔成功并告警。
- 旧收银台仍未付款：`SUPERSEDED` 尝试会调用渠道关闭；只有明确关闭或交易不存在才落 `CLOSED`。
- 查单成功但缺少 `trade_no` 或 `total_amount`：返回 `UNKNOWN`，保持原状态并告警，不能使用本地金额代替渠道金额。

## 手工账单对账工作台

后台“资金对账”页面支持导入支付宝交易账单 CSV/ZIP，按账期执行对账。第一版是 dry-run：只生成匹配和差异，不自动修改订单、不自动补权益、不自动退款。

对账链路：

1. 上传账单文件，按 `provider + statement_date + SHA-256` 去重。
2. 原始文件压缩保存，解析为标准化流水；表格按列名识别，支持 UTF-8、GB18030 和 ZIP。
3. 按商户订单号定位本地支付尝试，校验渠道交易号、金额和支付状态。
4. 生成 `PROVIDER_ONLY`、`LOCAL_ONLY`、`AMOUNT_MISMATCH`、`STATUS_MISMATCH`、`TRADE_NO_MISMATCH`、`DUPLICATE_PROVIDER_TRADE`、`DUPLICATE_PAYMENT`、`REFUND_MISMATCH` 等差异。
5. 差异必须经过认领、解决或忽略动作，动作写入 `t_recon_action`，运行记录保留历史版本。

演示文件位于 `docs/对账演示账单.csv`。真实账单上传前应先脱敏，不要把完整账单或签名 URL 放进日志。

当前版本仍有明确边界：不做自动补单、不做自动退款、不做手续费/结算净额对账，也尚未检测“本地退款成功但渠道账单完全缺失”的单边退款。支付宝账单 API 自动下载需要单独开通账单权限；没有权限时先使用商户后台导出的 CSV/ZIP。

## 退款

退款按 `attempt_id` 唯一，不再按订单唯一。处理过程使用租约：

- 同一时间只有一个 worker 可以调用渠道。
- 渠道成功是单调结果，可以覆盖先前的 `FAILED`。
- 渠道失败只能在持有当前租约且退款仍为 `PROCESSING` 时落账，不能覆盖成功。
- 网络超时保留重试，退款号 `out_request_no` 保持稳定以保证支付宝侧幂等。

后台“订单管理”的支付尝试页可对非主交易的成功 attempt 发起“退重复款”。该操作不改变订单状态，也不回收课程权益。主支付退款仍使用订单级“发起退款”。

## 告警与处置

- `PAYMENT_DUPLICATE_SUCCESS`：发现第二笔成功付款。
- `PAYMENT_DUPLICATE_UNREFUNDED`：重复付款尚未退款，按后台 attempt 发起退款。
- `PAYMENT_MANUAL_REVIEW`：已付费但订单终态需要人工核对，后台事件状态为 `MANUAL_REVIEW`。
- `payment.query.unknown` 指标和错误日志：渠道查单返回缺字段或未知状态，禁止自动发货。

生产环境应配置 `ALERT_WEBHOOK_URL`，否则这些告警只会写入 `t_alert_log`，需要人工巡检。

## 尚未覆盖

当前实现完成的是“订单/支付尝试/回调/主动查单”一致性，不等同于支付宝账单级对账。账单级对账需要额外接入支付宝账单下载权限，按日比对渠道账单与本地成功 attempt，属于独立的数据对账任务。
