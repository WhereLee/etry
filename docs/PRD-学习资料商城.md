# PRD：学习资料商城（btry 重写 v1）

> 定位：个人面试项目，部署在个人域名下演示，不涉及真实交易。
> 来源：用户决定「做一个卖学习资料的，比如电子版课本、电子版试卷或者电子版教辅」；
> 购物车：用户下令「购物车加一下吧」；分销员：用户明确「先不做了」。
> 支付内核（支付宝电脑网站支付 + mock）从现有项目迁移复用，不重写资金逻辑。

## 1. 商品与内容

- 商品 = 电子资料（试卷 / 教辅 / 讲义 / 电子课本），PDF 为主
- 数据来源方便：演示资料由项目生成（PDFBox 生成带水印示例 PDF），不依赖外部资源采购
- 商品属性：标题、分类（试卷/教辅/讲义/课本）、学段/学科标签、价格（分）、封面、简介、页数、文件
- 免费试读：预览前 N 页（带「试读」水印）；购买后下载完整文件（带购买者水印）
- 搜索：MySQL 8 ngram 全文索引（v1 不引入 Elasticsearch）

## 2. 用户身份与需求（v1 范围）

| 身份 | 核心需求 |
|---|---|
| 游客 | 浏览目录、搜索、看详情与试读；下单前引导注册/登录 |
| 买家（注册学生/家长） | 自助注册、购物车、支付宝下单支付、订单查询、已购资料列表、下载、申请整单退款 |
| 运营 | 资料上下架、分类/标签维护、价格管理、首页推荐位 |
| 客服 | 查订单/支付/退款状态、处理退款申请、查看用户已购权益 |
| 财务 | 对账（渠道账单 vs 平台流水）、退款复核、导出报表（EasyExcel） |
| 超级管理员 | 账号与角色权限管理（RBAC）、审计日志、系统配置 |

不做：分销员、作者入驻、机构采购、审核流（v1 运营直接上架）。

身份模型原则：身份（Role）≠ 账号状态（Status）≠ 已购权益（Entitlement）≠ 标签（Tag），避免角色爆炸。

## 3. 购物与交易（v1）

- 购物车：仅登录用户；t_cart_item 唯一 (user_id, material_id)，数量恒 1（电子资料不重复购买）；已购商品加购时提示
- 下单：购物车勾选结算 → 订单头 t_order + 明细 t_order_item（标题/价格快照）；client_request_id 幂等
- 支付：支付宝电脑网站支付（FAST_INSTANT_TRADE_PAY），subject「资料订单 共N件」；mock  provider 保留 7 场景用于演示/测试；订单 15 分钟过期
- 履约：支付成功 → 权益中心 t_entitlement 授予（product_type=MATERIAL）→ 可下载
- 退款：v1 仅整单退款；退款成功回收权益；fundChange 校验 + 退款查询确认（复用现有内核）
- 对账：渠道账单解析 + 流水对账 + 管理端对账页（复用合并分支成果）

## 4. 权限（企业标准，不简化）

- RBAC：角色 + 权限点 + 数据范围 + 审计；Spring Security 完整落地（阶段1已行为保持接入）
- 预置角色：BUYER / OPERATOR / CUSTOMER_SERVICE / FINANCE / SUPER_ADMIN
- 管理端接口按权限点鉴权，写操作进审计日志

## 5. 非功能

- 并发安全：下单/支付回调/退款幂等与并发测试（JUnit CountDownLatch + 集成测试）
- 可观测：沿用 actuator + Prometheus + Grafana + Jaeger（可选栈）
- CI：单测 + 集成 + package + 前端 lint/build + docker compose build（阶段1已加固）
- 国内镜像：Maven 阿里云 / npm npmmirror / Docker 部署机镜像源

## 6. 验收口径

- mock 全链路可演示：注册 → 加购 → 结算 → mock 支付 → 下载 → 整单退款 → 对账
- 真实支付宝 ¥0.01 验收需用户商户账号（沙箱/真实均可），未提供前以 mock 为准
- 每阶段门禁：编译 → 单测 → 启动+接口验证（含异常分支）→ 并发验证 → 日志/总结 → 提交推送盯 CI
