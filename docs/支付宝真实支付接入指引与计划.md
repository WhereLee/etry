# 支付宝真实支付接入指引与计划

更新日期：2026-11-03

当前状态（2026-11-05 更新）：支付宝电脑网站支付已接入并部署到 `whereri.site/learn/`，本地保留 Mock 渠道。本文主体仍是签约前的企业/个体户规划口径；个人账号的实际额度、费率与退款规则以 `docs/生产运维手册.md` §2、§12 为准。

目标：先在支付宝沙箱完成真实协议联调，再切换生产商户配置并进行低金额实付验收。

## 1. 你需要从支付宝准备什么

最终代码需要以下数据。敏感值只放本机环境变量或受控密钥文件，不进入 Git、聊天记录或前端代码。

| 配置项 | 来源 | 是否敏感 |
|---|---|---|
| `ALIPAY_APP_ID` | 开放平台应用详情 | 否 |
| `ALIPAY_APP_PRIVATE_KEY` | 本地密钥工具生成，自己保存 | 是 |
| `ALIPAY_PUBLIC_KEY` | 上传应用公钥后由支付宝生成 | 否，但只能使用当前应用对应值 |
| `ALIPAY_SELLER_ID` | 商家平台/交易通知中的 PID | 否 |
| `ALIPAY_NOTIFY_URL` | 你自己的公网 HTTPS 后端接口 | 否 |
| `ALIPAY_RETURN_URL` | 支付完成后的前端返回页 | 否 |
| `ALIPAY_GATEWAY_URL` | 官方生产或沙箱网关 | 否 |
| 商家签约状态 | 商家平台产品中心 | 否 |
| 企业营业执照/结算账户 | 商家认证和签约 | 是，不进入代码 |

推荐先使用“公钥模式（RSA2）”，不先使用证书模式。公钥模式配置更直接，后续有需要再迁移证书模式。

## 2. 支付宝后台操作步骤

### 2.1 商家认证与产品签约

1. 注册或登录支付宝商家平台：<https://b.alipay.com/>
2. 完成企业或个体工商户实名认证，绑定可结算账户。
3. 进入商家平台“产品中心”。
4. 找到“电脑网站支付”，提交签约。
5. 按页面要求准备营业执照、网站地址、主体信息等资料。
6. 等待产品签约通过。未签约时即使有 APPID，也不能正常调用电脑网站支付。

官方参考：

- 电脑网站支付签约：<https://opendocs.alipay.com/b/03ai91>
- 电脑网站支付申请条件：<https://opendocs.alipay.com/b/03ah5w>

### 2.2 创建开放平台应用

1. 登录支付宝开放平台：<https://open.alipay.com/>
2. 进入控制台，选择创建应用。
3. 应用类型选择“网页&移动应用”。
4. 接入场景选择支付接入。
5. 填写应用名称、网站地址等资料。
6. 创建成功后，在应用详情获取 `APPID`。

官方参考：

- 创建应用：<https://opendocs.alipay.com/open/200/105310>

### 2.3 绑定电脑网站支付产品

1. 打开刚创建的应用。
2. 进入产品绑定/能力列表。
3. 绑定已经签约成功的“电脑网站支付”。
4. 确认产品状态为已生效或已开通。

### 2.4 配置 RSA2 密钥

1. 下载支付宝开放平台密钥工具。
2. 选择 RSA2 和 PKCS8 格式，生成应用公钥、应用私钥。
3. 应用私钥只保存在本机安全位置，不上传开放平台、不发到聊天、不提交 Git。
4. 在应用详情的“开发设置/接口加签方式”中选择公钥模式。
5. 上传“应用公钥”。
6. 上传成功后，开放平台会生成“支付宝公钥”，把它保存到本机配置。
7. 记录密钥对应的 APPID，不同应用的密钥不能混用。

注意：

- 应用公钥上传给支付宝。
- 应用私钥由你保留，用于请求加签。
- 支付宝公钥由支付宝平台生成，用于回调验签。
- RSA2 默认 PKCS8；如生成 PKCS1，需要格式转换。

官方参考：

- 生成及配置 RSA2 密钥：<https://opendocs.alipay.com/support/01raut>
- 获取支付宝公钥：<https://opendocs.alipay.com/support/01rauu>

### 2.5 配置公网 HTTPS 回调

真实支付和支付宝沙箱联调都需要支付宝能够访问你的异步通知地址。

- 异步通知示例：`https://your-domain/api/payments/alipay/notify`
- 支付返回页示例：`https://your-domain/orders/{orderNo}` 或统一订单页
- `127.0.0.1`、局域网 IP、没有 TLS 的地址不能作为生产回调。
- 生产必须使用稳定域名、有效 HTTPS 证书和正确的反向代理转发。
- 如果当前没有公网域名，只能先做沙箱或临时隧道联调，不能做真实生产回调验收。

当前项目没有支付宝回调入口，代码计划会新增公开但必须验签的 `/api/payments/alipay/notify`。

### 2.6 先准备沙箱

正式资金测试前，建议先使用支付宝沙箱：

- 沙箱 APPID、密钥和生产完全隔离。
- 沙箱有独立买家/商家账号和沙箱版支付宝 App。
- 沙箱网关：`https://openapi-sandbox.dl.alipaydev.com/gateway.do`
- 生产网关：`https://openapi.alipay.com/gateway.do`

沙箱文档：<https://opendocs.alipay.com/common/05yvy1>

## 3. 当前项目还缺什么

业务链路已经具备：

- 订单、价格快照、支付尝试、支付事件。
- `PAID -> FULFILLED` 履约拆分。
- 权益幂等、退款、补偿、主动查单。
- 管理端异常订单和人工补偿。

真实支付宝还缺协议和运行边界：

- 官方 SDK 和支付宝网关调用。
- RSA2 请求加签、回调验签。
- 公网异步通知入口。
- 支付宝交易状态映射。
- 交易查询和退款查询适配。
- 真实渠道的支付动作返回。
- 生产密钥、证书和公网域名。
- 真实渠道对账和异常订单处置。

## 4. 代码改造计划

### 批次 A：配置与安全边界

新增 `AlipayProperties`：

- `appId`
- `appPrivateKey`
- `alipayPublicKey`
- `sellerId`
- `gatewayUrl`
- `notifyUrl`
- `returnUrl`
- `signType=RSA2`
- `charset=utf-8`
- `enabled`

约束：

- 生产只允许 `PAYMENT_PROVIDER=alipay`。
- 沙箱使用 `PAYMENT_PROVIDER=alipay-sandbox`。
- Mock 继续禁止在 `prod` profile 启用。
- 私钥不打印、不返回前端、不写日志。
- 启动时校验必要配置，缺失直接 fail-fast。

### 批次 B：支付网关适配

新增 `AlipayPaymentGateway implements PaymentGateway`。

改动：

- `initiate`：调用 `alipay.trade.page.pay`。
- `query`：调用 `alipay.trade.query`。
- `refund`：调用 `alipay.trade.refund`。
- 退款结果未知时调用 `alipay.trade.fastpay.refund.query`。
- 渠道标识使用 `ALIPAY`。

当前 `PaymentAction` 需要扩展为：

- `MOCK`：继续返回 Mock 收银台地址。
- `REDIRECT`：返回支付宝支付跳转地址，前端执行跳转。
- 如 SDK 只能返回表单，再增加 `FORM` 类型，由前端安全提交表单。

建议先验证 SDK 的 `pageExecute` 是否可直接得到 GET 跳转 URL；如果不能，就使用表单模式。

### 批次 C：异步通知

新增公开接口：

`POST /api/payments/alipay/notify`

实现：

1. 接收支付宝表单参数。
2. 使用支付宝公钥做 RSA2 验签。
3. 校验 APPID、seller_id、out_trade_no、total_amount。
4. 映射交易状态。
5. 转成现有 `PaymentNotification`。
6. 复用 `PaymentConfirmationService` 和 `OrderFulfillmentService`。
7. 成功返回纯文本 `success`，失败返回 `failure`。

安全要求：

- 路径加入 `JwtAuthFilter` 公开路径，但不能跳过验签。
- 不信任 `return_url`。
- 回调请求体限制大小。
- 通知原文只保存摘要，不保存敏感完整报文。
- 重复通知由 `(provider,event_key)` 唯一键处理。
- 生产日志隐藏私钥、签名和付款人敏感信息。

状态映射：

- `WAIT_BUYER_PAY`：订单保持 `PAYING`。
- `TRADE_SUCCESS`：进入支付确认。
- `TRADE_FINISHED`：已完成交易，不能再次履约。
- `TRADE_CLOSED`：支付失败或关闭，按订单当前状态谨慎处理。

### 批次 D：前端支付动作

当前 `OrderDetail.vue` 只认识 Mock 收银台地址。

改造：

- `POST /api/orders/{orderNo}/pay` 返回 `actionType`。
- `MOCK` 跳转 `/mock-pay/...`。
- `REDIRECT` 跳转支付宝支付地址。
- `FORM` 安全提交支付宝表单。
- 支付返回页继续轮询订单状态，不能把返回参数当成功。
- 增加“支付结果查询中”和“支付宝已返回，等待服务器确认”提示。

### 批次 E：沙箱验收

- 使用沙箱 APPID、私钥、支付宝沙箱公钥。
- 用沙箱版支付宝 App 和测试买家账号支付。
- 验证支付成功、取消、超时、重复回调、回调丢失和退款。
- 验证主动查单可以补偿丢失通知。
- 验证金额校验和 app_id/seller_id 校验。
- 沙箱通过前不进入生产配置。

### 批次 F：生产小额验收

前置条件：

- 商家认证和电脑网站支付签约通过。
- 生产 APPID、私钥、支付宝公钥和 seller_id 已配置。
- 公网 HTTPS 回调可用。
- 数据库已备份。
- 管理端可以查询订单和发起退款。

验收：

1. 管理员将测试课程设为最低价格。
2. 真实支付一笔低金额订单。
3. 检查支付宝交易号、订单号、金额和权益。
4. 管理员发起全额退款。
5. 核对订单 `REFUNDED`、权益撤销和支付宝退款状态。
6. 检查回调日志、`traceId`、指标和告警。

## 5. 建议环境变量

```text
PAYMENT_PROVIDER=alipay-sandbox
ALIPAY_APP_ID=沙箱APPID
ALIPAY_APP_PRIVATE_KEY_FILE=C:\secure\alipay\app-private-key.pem
ALIPAY_PUBLIC_KEY_FILE=C:\secure\alipay\alipay-public-key.pem
ALIPAY_SELLER_ID=2088...
ALIPAY_GATEWAY_URL=https://openapi-sandbox.dl.alipaydev.com/gateway.do
ALIPAY_NOTIFY_URL=https://your-dev-domain/api/payments/alipay/notify
ALIPAY_RETURN_URL=https://your-dev-domain/orders
ALIPAY_SIGN_TYPE=RSA2
ALIPAY_CHARSET=utf-8
```

生产切换：

```text
PAYMENT_PROVIDER=alipay
ALIPAY_GATEWAY_URL=https://openapi.alipay.com/gateway.do
```

私钥优先使用文件路径，不直接放环境变量明文。生产环境应使用系统密钥管理或受控配置文件，并限制运行账号读取权限。

## 6. 你需要提供给我的信息

第一阶段只需要非敏感信息：

- 支付模式：沙箱还是生产。
- APPID。
- `seller_id`。
- 网站访问域名。
- 公网回调地址是否已经具备。
- 电脑网站支付是否已签约。
- 使用公钥模式还是证书模式。
- 支付返回页希望落到订单详情页还是统一结果页。

敏感信息不要发到聊天：

- 应用私钥。
- 含私钥的证书文件。
- 商家账号密码。
- 支付宝登录验证码。
- 结算账户信息。

私钥由你放到本机受控路径，代码通过文件路径读取。

## 7. 推荐执行顺序

1. 你先完成支付宝商家认证并签约电脑网站支付。
2. 创建开放平台应用并拿到 APPID。
3. 配置沙箱 APPID、RSA2 公钥模式、应用私钥和支付宝公钥。
4. 准备一个支付宝可访问的 HTTPS 域名或临时隧道。
5. 我实现沙箱适配、通知入口和前端支付跳转。
6. 沙箱通过后，再切生产 APPID、密钥、seller_id 和回调域名。
7. 使用 ¥1.99 课程完成一笔真实低金额支付和全额退款。
8. 检查订单、权益、支付事件、退款、指标和日志后，才正式启用。

## 8. 明确不做

- 不在前端保存私钥。
- 不根据 `return_url` 参数直接发货。
- 不接受未验签的通知。
- 不允许回调重复生成权益。
- 不用 Mock 替代真实资金测试。
- 不在未签约电脑网站支付时硬编码绕过产品状态。
