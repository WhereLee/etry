## 2. 自动化与接口验收

`tools/payment-smoke.ps1` 连续通过：

| 场景 | 预期 | 结果 |
|---|---|---|
| 正常支付 | 订单 `FULFILLED`，生成权益 | PASS |
| 支付失败 | `PAY_FAILED`，不生成权益，可关闭 | PASS |
| 回调丢失 | 主动查单后 `FULFILLED` | PASS |
| 重复通知 | 只生成一条权益，订单完成一次 | PASS |
| 履约失败一次 | 先 `PAID`，补偿后 `FULFILLED` | PASS |
| 退款失败后重试 | `REFUND_FAILED -> REFUNDED`，最终撤销订单权益 | PASS |
| 金额不一致 | 保持 `PAYING`，支付事件标记失败并告警 | PASS |
| Redis 停止 | 下单、支付、权益发放、退款仍成功 | PASS |

金额不一致场景会留下异常订单，供管理员人工处理，不自动发货。

## 3. 浏览器验收

- 管理员在内容管理中看到销售状态和价格，并可打开销售设置。
- 购课体验学员进入课程商店，看到两个在售系列及价格。
- 学员点击购买后生成订单并进入订单详情。
- 订单详情可发起支付、关闭未支付订单、显示时间线并轮询状态。
- Mock 收银台显示订单、金额、正常支付按钮和故障演练场景。
- 支付成功后订单显示 `已完成`，课程进入学习空间并可播放。
- 管理员订单页可以查看支付尝试、支付事件、权益和退款。
- 管理员发起退款后订单变为 `已退款`，订单来源权益被撤销。
- 桌面默认视口和 390px 窄屏均完成页面检查。
- 浏览器控制台无 error/warning。

## 6. 当前限制

- 只有 Mock 支付，没有真实支付宝网络调用。
- 真实支付需要支付宝沙箱/商户资质、公网 HTTPS 回调地址和生产密钥。
- 管理员退款为全额退款，不支持部分退款和用户自助退款。
- 支付回调采用站内 Mock 事件签名与统一确认服务，真实渠道接入时替换网关适配层。
- 智能客服未实现，仅保留订单状态时间线数据。
