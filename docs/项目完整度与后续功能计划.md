## 2. 产品边界

目标是教培机构内部使用的录播课程平台，不扩展成综合教务系统。

保留：

- 管理员统一管理账号和学习权限：学员由管理员建号，教师通过管理员邀请完成注册。
- 教师维护自己的系列、章节、视频和发布状态。
- 学员只看到已分配且已发布的系列。
- 管理员可处理账号和紧急内容问题。

明确不做：

- 公开自助注册。教师邀请链接注册不属于公开注册，必须由管理员生成一次性邀请。
- 评论、评分、问答、论坛。
- 直播、连麦、作业批改。
- 多租户 SaaS。
- 复杂课程审核工作流。
- 独立移动端。
- 支付前置。

## 3. 目标角色职责

### 3.1 管理员

- 创建、禁用、重置学员账号。
- 生成、复制、撤销教师邀请链接。
- 查看教师邀请状态。
- 为学员分配已发布系列。
- 查看全部系列和账号。
- 处理内容异常和账号异常。
- 不承担教师日常内容编辑职责。

### 3.2 教师

- 通过管理员发出的邀请链接完成注册，自行设置密码。
- 登录教师工作台。
- 只查看和维护自己的系列。
- 创建、编辑、排序系列、章节和视频。
- 保存草稿、发布、下架自己的系列。
- 不能管理账号，不能给学员分配系列。
- 不能编辑其他教师的系列。

### 3.2.1 教师邀请制注册规则

- 不提供公开注册入口。
- 只有管理员可以生成邀请。
- 邀请时预先绑定教师用户名和昵称，教师不能通过邀请创建管理员或其他角色。
- 邀请链接一次性使用，默认 72 小时过期。
- 数据库只保存 token 哈希，不保存明文 token。
- 教师打开链接后设置自己的密码，密码继续使用 8-32 位、字母 + 数字和弱密码校验。
- 注册成功后邀请立即失效，账号角色固定为 `TEACHER`。
- 管理员可撤销未使用的邀请。
- 当前不接邮件服务，管理员生成链接后通过内部渠道发送；后续可增加邮件邀请而不改变核心模型。
- 邀请创建、撤销和注册成功都要进入管理员审计或账号审计。

建议接口：

- `POST /api/admin/teacher-invitations`：生成邀请。
- `GET /api/admin/teacher-invitations`：查看邀请状态。
- `PUT /api/admin/teacher-invitations/{id}/revoke`：撤销邀请。
- `GET /api/auth/teacher-invitations/{token}`：校验邀请并返回绑定的用户名/昵称。
- `POST /api/auth/teacher-invitations/accept`：设置密码并创建教师账号。

建议数据表 `t_teacher_invitation`：

- `id`；
- `token_hash`；
- `username`；
- `nickname`；
- `status`：`PENDING / USED / REVOKED`；
- `expires_at`；
- `created_by`；
- `used_by`；
- `created_at`；
- `used_at`。

### 3.3 学员

- 登录学习空间。
- 只看到“已分配 + 已发布”的系列。
- 进入系列播放页观看录播视频。
- 不承担内容管理能力。

## 4. 发布批次

### 批次 A：教师邀请注册、入口与资源归属

目标：先让教师安全地看到自己的工作范围，不立刻引入内容编辑复杂度。

功能：

- 管理员生成、复制和撤销教师邀请链接。
- 教师通过一次性链接设置密码并激活账号。
- 教师登录后进入教师工作台。
- “我的系列”只展示当前 `teacher_id` 拥有的系列。
- 前端路由区分管理员、教师、学员首页。
- 教师访问学员管理接口或他人系列时，后端返回 `403`。
- 管理员仍可查看全部系列。

技术要点：

- 新增教师邀请表和公开的邀请校验/接受接口。
- 邀请 token 使用安全随机值，数据库只存哈希。
- 接受邀请时在同一事务中完成“邀请置为 USED + 创建教师账号”。
- 使用条件更新防止同一邀请被并发使用。
- 邀请接受接口增加限流和审计。
- 新增教师端路由和导航。
- 新增 `/api/teacher/series`。
- 在 Service 层校验 `series.teacher_id == currentUserId`。
- 增加教师所有权测试，而不是只依赖前端隐藏按钮。

验收：

- 未持有有效邀请不能注册教师。
- 同一邀请只能成功使用一次，过期或撤销后不可用。
- 邀请只能创建 `TEACHER`。
- 教师激活后可以登录教师工作台。
- 教师只能看到自己的系列。
- 教师不能分配账号或系列。
- 学员不能进入教师工作台。
- 管理员可以查看所有系列。

### 批次 B：系列、章节、视频管理

目标：完成不含上传的课程结构编辑闭环。

功能：

- 创建系列：标题、简介、排序。
- 编辑和归档系列。
- 创建、编辑、排序、删除章节。
- 创建、编辑、排序、删除视频元数据。
- 草稿、已发布、已下架三种状态：
  - `DRAFT`：只有教师和管理员可见；
  - `PUBLISHED`：管理员可分配，学员可见；
  - `ARCHIVED`：不再新增分配，已分配学员按策略只读或不可见。
- 学员学习空间只返回 `PUBLISHED` 系列。
- 管理员只能分配 `PUBLISHED` 系列。

数据模型建议：

- `t_series` 增加：
  - `status`；
  - `updated_at`；
  - 可选 `published_at`。
- 章节和视频仍使用现有排序字段。
- 删除采用受限策略，优先阻止删除已有学员关系或播放记录的系列。

验收：

- 教师可以独立完成一个系列的结构搭建。
- 草稿不会出现在管理员分配列表和学员学习空间。
- 教师不能编辑他人系列。
- 发布后的系列可以被管理员分配。

### 批次 C：视频上传与媒体处理

目标：把“内容结构编辑”补成“教师可以真正交付视频”的闭环。

功能：

- 教师为视频申请上传地址。
- 浏览器直传 COS，不经过应用主机转发视频文件。
- 上传完成后调用后端确认对象存在。
- 保存对象键、文件大小、时长和媒体状态。
- 上传失败可重试。
- 视频未就绪时不允许发布系列。
- 发布前校验章节和视频顺序完整。

建议技术方案：

- COS 预签名 PUT 上传。
- 上传完成后后端通过 HEAD 或元数据接口确认对象。
- 视频时长优先由预处理结果写入；无法获取时标记待处理。
- 大文件不做应用内存缓冲。
- 上传和发布操作继续使用审计、限流和幂等。

验收：

- 教师可以创建系列、添加章节、上传视频并发布。
- 学员能播放新上传视频。
- 上传失败不会留下“已发布但不可播放”的系列。
- 普通学员不能获得上传地址。

### 批次 D：学员学习体验补全（按需）

这批不是教师端前置条件，只有在真实使用中需要时再做。

候选功能：

- 最近学习位置。
- 播放进度。
- 已看/未看标记。
- 系列完成度。
- 续播。

原则：

- 先做最小进度记录，不做积分、排行榜和打卡。
- 进度是辅助能力，不能阻塞播放主链路。
- 如果机构只要求“能看课”，此批次可以长期不做。

### 批次 E：管理员内容治理

功能：

- 查看全部系列及发布状态。
- 查看教师内容数量和最近更新时间。
- 管理员下架异常系列。
- 管理员分配前只能选择已发布系列。
- 查看账号与系列分配关系。

不做：

- 复杂审批流。
- 多级审核。
- 内容评分。
- 课程运营活动。

### 批次 F：收费与学习权限（明确不进入 v1）

当前学习权限由管理员分配系列产生，已经满足内部培训场景。收费不进入当前项目范围，也不作为后续待办持续提醒。

v1 之后已按 `docs/订单与Mock支付实施方案.md` 完成 Mock 支付、权益、补偿和对账闭环，验收见 `docs/订单与Mock支付验收记录.md`。支付宝电脑网站支付已于 2026-11-05 接入并部署，微信支付仍在后续阶段。

如果未来业务明确转为对外招生，再单独立项并按以下边界拆分：

- 订单：支付、退款、状态机。
- 权益：订单成功后生成学员系列权益。
- 播放：只认权益，不直接读订单。

这样支付故障不会直接破坏播放主链路。该方案仅作为未来扩展边界记录，当前不创建订单、支付或权益代码。

## 5. 推荐实施顺序

1. 批次 A：教师邀请注册、教师入口、我的系列、归属校验。
2. 批次 B：系列/章节/视频元数据 CRUD 与发布状态。
3. 批次 C：COS 直传、对象确认和发布前完整性校验。
4. 批次 D：根据真实教学需求决定是否补学习进度。
5. 批次 E：管理员内容治理和运行视图。
6. 批次 F：收费、订单和权益，当前明确不做。

这个顺序的原因：

- 先把角色边界做对，再给教师编辑能力。
- 先让数据结构可控，再接入真实上传。
- 先保证内容可发布、可分配、可播放，再谈学习进度。
- 支付不属于当前内部使用场景，不应反复进入收口范围。

## 6. 技术约束

- 教师数据隔离必须在后端完成，不能只隐藏菜单。
- 发布状态必须影响学员查询和分配接口。
- 视频上传使用 COS 直传，不把大文件经过应用主机转发。
- 内容写操作继续复用 AOP 审计、限流、幂等和指标。
- 所有新增写操作需要事务边界和失败回滚。
- 新增接口需要权限测试、归属测试和状态测试。
- 日志继续携带 `traceId`。
- 不引入评论、评分和复杂审批状态机。

## 7. 完成标准

项目可称为“内部可用完整版”时，至少满足：

- 管理员能创建学员账号、邀请教师并分配已发布系列。
- 教师能通过邀请激活账号、登录、创建自己的课程结构、上传视频并发布。
- 学员能登录、只看到已分配且已发布的系列，并正常播放。
- 教师不能管理账号，不能编辑他人内容。
- 草稿和未完成视频不会被学员看到。
- 内容写操作可审计，失败可定位。
- 备份、恢复、本地启停、日志和监控满足内部生产要求。

收费、评论、评分和复杂审核不属于当前 v1 完成标准，不应继续阻塞收口。
