# btry 前端界面与组件规范

更新日期：2026-11-02

## 1. 目标

前端定位是机构内部录播学习平台，不是营销落地页。界面首先保证：

- 课程、账号、发布状态等业务信息清楚。
- 表单、表格、弹窗、加载和失败状态一致。
- 桌面端和窄屏都能完成主要操作。
- 视觉有明确识别度，不落入常见 AI 生成模板。

## 2. 视觉方向

当前采用“内部学院 / 纸感编辑风”：

- 暖纸色背景，深墨绿为主要操作色。
- 陶土色用于序号、强调和关键提示。
- 标题使用宋体类衬线字体，正文使用系统无衬线字体。
- 管理端使用深色侧栏，学员端使用轻量顶栏。
- 卡片以边框、留白和细线组织，不使用大面积渐变、玻璃拟态或满屏阴影。

设计变量定义在 `web/src/style.css`，新增页面必须复用已有变量，不直接写新的主色和字体。

## 3. 组件与依赖

- Vue 3 + Vue Router + Axios。
- Element Plus 2.14.7，用于表单、输入、表格、分页、弹窗、标签、进度、骨架屏和空状态。
- `@element-plus/icons-vue` 统一图标来源。
- `unplugin-vue-components` 按需引入 Element Plus 组件和样式。

约束：

- 不重新引入 `element-plus/dist/index.css` 全量样式。
- 不在页面里混用第二套图标库。
- 原生控件只保留无法由组件库覆盖的场景，例如视频文件选择。
- 公共页头使用 `PageHeader.vue`，状态标签使用 `StatusTag.vue`。

2026-11-02 构建对比：

- 全量引入时主 JavaScript 分块约 1.07 MB。
- 改为按需引入后，最大页面相关分块约 203 KB；表格组件单独成块约 197 KB。

## 4. 页面模式

### 表单页

- 使用 `el-form` + `el-form-item`。
- 字段错误和接口错误使用 `el-alert`，不只修改占位文字。
- 提交按钮必须有 loading 状态，提交期间禁止重复操作。
- 密码输入使用 `show-password`，登录和激活页保留清晰的账号提示。

### 列表页

- 筛选使用 `el-input` / `el-select`。
- 数据表使用 `el-table`，分页使用 `el-pagination`。
- 加载使用 `v-loading` 或 `el-skeleton`。
- 无数据使用 `el-empty`，接口失败提供重新加载入口。
- 行操作使用文字按钮，危险操作必须二次确认。

### 播放页

- 视频区域和课程目录保持主次关系。
- 进度、已看状态和续播信息不能遮挡播放器。
- 视频仍使用 COS 预签名直连，前端改造不改变播放协议。
- 窄屏下目录移动到播放器下方。

## 5. AI 前端问题的规避清单

在线调研参考：

- Common Problems in AI-Generated Frontend Code：<https://karishma.dev/blogs/ai-generated-frontend-code-problems>
- How to fix the “AI-generated” look in your frontend：<https://dev.to/alanwest/how-to-fix-the-ai-generated-look-in-your-frontend-1ahh>

调研中反复出现的问题与本项目处理：

| 问题 | 本项目处理 |
|---|---|
| 默认蓝紫渐变、居中 Hero、三卡片模板 | 改用暖纸、墨绿、陶土和不对称编辑式排版 |
| 所有组件统一大圆角和重阴影 | 统一小半径边框卡片，阴影只用于层级提示 |
| 默认组件库视觉直接铺满全站 | 覆盖 Element Plus 主题变量，并用业务布局包裹 |
| 全量引入组件库导致包体过大 | Vite 按需解析组件和样式 |
| 加载、错误、空数据状态缺失 | 列表、播放器、详情和表单都提供状态反馈 |
| 重复登录表单和弹窗实现 | 统一使用 Element Plus 表单和 Dialog |
| 按钮点了没反应 | 保留原有业务处理函数，并逐页走浏览器验收 |
| 颜色、间距、字号随意漂移 | 统一定义设计变量和三个响应式断点 |
| 表单状态和校验分散 | 输入组件统一，业务校验仍留在页面逻辑 |
| 只适配桌面宽度 | 管理端移动导航、学员端移动顶栏和单列卡片已验证 |

## 6. 响应式与可访问性

- 900px：管理端侧栏切换为顶部移动导航。
- 760px：页面标题、操作区和表格工具栏改为纵向排列。
- 640px：课程卡片、筛选项和编辑器字段改为单列。
- 主要交互元素支持键盘焦点。
- 输入框依赖 Element Plus 的焦点环，不再叠加浏览器默认粗轮廓。
- 错误不能只靠颜色表达，必须同时有文字说明。
- 视频播放保留原生 controls，确保键盘和系统快捷键可用。

## 7. 验收要求

每次前端改动至少执行：

```powershell
cd web
npm run build
```

涉及业务页面时继续验证：

- 管理员：用户管理、教师邀请、内容管理。
- 教师：系列列表、系列详情、编辑器、发布状态。
- 学员：学习空间、系列播放、进度和续播。
- 桌面视口和 390px 窄屏各检查一次。
- 浏览器控制台无 error/warning。
- 不新增测试邀请、测试账号或学习进度；若产生，验收后清理。

## 8. 后续约束

- 视觉新增先复用变量和公共组件，再考虑新增依赖。
- 需要新组件时优先使用 Element Plus 现有能力。
- 不为了“看起来现代”添加无业务作用的动画、图表或装饰层。
- 页面改造不能改变视频直连 COS、权限校验和业务状态规则。
