# 阶段4总结：交易闭环（购物车结算 → 多商品订单 → 支付 → 履约 → 退款）

## 一、本阶段做了什么

业务依据：PRD-学习资料商城 §3（购物车勾选结算、订单头+明细快照、client_request_id 幂等、15 分钟过期、MATERIAL 履约、v1 仅整单退款且退款回收权益、对账复用）。

### 后端
- **CartCheckoutService**（commerce.cart）：勾选行 → 多商品订单。
  - 幂等双保险：`uk_order_client_request` 唯一键 + 进行中订单含同资料时直接复用（过期且未支付则先关闭）。
  - 校验链：未加购 400 → 逐行经 `SellableCatalog(MATERIAL)` 取可售与价格快照（下架 400）→ 逐行 `EntitlementQuery.hasActive` 已购拦截 400 → 币种一致性边界校验 → 合计。
  - 订单头 `product_type=MATERIAL`、标题「资料订单 共N件」、`active_key=NULL`（单商品列 NULL，`productId==0` 为购物车订单标记）；`t_order_item` 写标题/价格快照；结算成功清空对应购物车行；`DuplicateKeyException` 兜底回读既有订单。
- **OrderRepository**：`insertCartOrder`（KeyHolder 回传 id）、`findActiveByMaterialIds`（JOIN 明细按资料找进行中订单）。
- **EntitlementRepository**：新增 productType 感知重载（hasActive/grantOrder/revokeOrder），旧签名委托 COURSE_SERIES，调用方零改动。
- **OrderFulfillmentService**：购物车订单逐明细行按 MATERIAL 发放/撤销；单商品订单按 `order.productType()` 路由（不再硬编码课程别名）。
- **PaymentService.pay**：购物车订单逐行已购校验（409「订单内资料已购买，请重新下单」）；FULFILLED 文案按商品类型区分。
- **MaterialFulfillmentHandler**（material 模块）：镜像 CourseFulfillmentHandler，仅依赖 commerce.api + entitlement.api 端口，ArchUnit 边界通过。
- **OrderService**：详情返回明细快照 `items`；购物车订单 `owned` 按「明细非空且全部已发放」计算；FULFILLED 时间线文案「资料权益已发放」。
- 支付宝 subject 复用 `productTitle`，购物车订单自动满足「资料订单 共N件」要求，无需改网关。

### 前端
- 购物车：行勾选（已购/下架行禁用）+ 全选 + 已选合计 + 结算按钮；`crypto.randomUUID()` 生成 clientRequestId；结算成功刷新购物车并跳订单详情，失败刷新购物车回显最新状态。
- 订单详情：标题改用 productTitle；新增「订单明细」快照卡片；金额标签/履约后按钮/PAID 提示按 MATERIAL 区分（前往我的学习空间、返回资料商城）。
- Mock 收银台：「课程」标签改「商品」（纯文案）。

## 四、当前阶段的已知缺陷

- **不同 clientRequestId 的并发结算窗口**：两请求同时通过「购物车含该行」与「无进行中订单」检查时，因购物车订单 active_key=NULL 无唯一键互斥，理论上可生成两张含同资料的订单。缓解：结算即清购物车（窗口极小）；先履约者使后单支付时被逐行已购校验 409 拦截，不会重复发放。前端单次结算复用同一 clientRequestId，双击场景已验证单订单。彻底互斥需引入资料级占位键，属新机制，留待用户决策。
- 币种一致性校验为订单头单 currency 字段的边界防御（现网资料全部 CNY，不会触发）。
- 权益下载/水印尚未实现（阶段5），FULFILLED 后「前往我的学习空间」暂沿用旧课程学习空间页面。
- 真实支付宝 ¥0.01 验收仍待用户商户账号，当前全链路为 Mock。
