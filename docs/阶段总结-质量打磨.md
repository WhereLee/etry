# 阶段总结：质量打磨（审查整改）

## 一、背景与范围

针对《全量交付审查报告》的 1 BLOCKER + 4 MAJOR + 6 MINOR 逐项整改，目标是把项目从「演示可跑」提升到「可上生产的工程基线」。本轮不改产品功能，聚焦部署安全、鉴权一致性、正确性、性能与文档准确性。

## 二、整改清单

### 批次A：部署生产口径（B1 / m2 / m6）
- **Mock 支付 fail-closed**：`application.yml` 与 `compose.yml` 的 `PAYMENT_MOCK_ENABLED` 默认 false；`provider=mock` 且未显式开启时 `PaymentSafetyGuard` 启动失败；prod profile 仍一律禁止 Mock。
- 本地演示由 `tools/start-local.ps1` 显式注入 `PAYMENT_PROVIDER=mock` / `PAYMENT_MOCK_ENABLED=true`，不影响开发体验。
- prod 关闭 springdoc（`api-docs` / `swagger-ui`），避免接口清单暴露。
- compose 补齐 `REDIS_DATABASE`、`ALIPAY_*`、`PAYMENT_MOCK_SECRET` 透传；`.env.docker.example` 端口改为 staging 的 18080/18084/19091，并明确 Mock 默认关闭。
- `deploy/setup-server.sh` 增加依赖预检（java/mysql/mysqldump/redis-server/nginx + JDK17 版本校验），缺失即失败退出。
- CI `docker-build` 增加 `docker compose config -q` 与 `bash -n` 部署脚本校验。

### 批次B：运营订单与异常映射（M1 / m1）
- 运营订单列表与关键词检索改用 `COALESCE(product_title_snapshot, series_title_snapshot)`，资料订单标题可见、可搜。
- 补齐 `HandlerMethodValidationException` / 参数类型不匹配 / 缺参 / 请求体不可读 的 400 映射，不再回落 500。

### 批次C：XFF 限流与备份（M2 / M3）
- `web/nginx.conf` 与 `deploy/Caddyfile.example` 改为**覆盖**写入 `X-Forwarded-For`（`$remote_addr` / `{remote_host}`），杜绝伪造 XFF 绕过登录 IP 限流；解析器补充代理契约注释。
- `deploy/btry-backup.sh` 增资料 PDF 目录 tar.gz 备份、保留期清理与恢复步骤注释；`tools/backup-mysql.ps1` 增资料目录打包。

### 批次D：性能与遗留鉴权（m3 / m4 / M4）
- 订单列表 N+1 改为批量：`OrderItemRepository.findByOrderIds` + 权益批量端口 `EntitlementQuery.findActiveIds`（与 `hasActive` 同谓词），列表一次预取明细与权益。
- 新增 `V24__refund_order_index.sql`：补 `t_refund(order_id)` 索引。
- 遗留运营端迁移到 RBAC：
  - 系列治理 → `hasRole('SUPER_ADMIN')`（**保持原 ADMIN 访问集合不变**，不把权限扩到 OPERATOR）；
  - 教师邀请 → `user:manage`。
  - 撤销 RBAC 角色后即使 `t_user.role` 仍为 ADMIN 也立即 403。

### 批次E：文档与门禁
- 修正 README 注册口径、演示脚本按钮名、Docker 文档过期 RBAC 表述、运维手册 Windows/systemd 措辞与场景计数；Flyway 版本更新为 V24。
- 新增 5 个测试类（`PaymentSafetyGuardTest`、`ApiErrorContractIntegrationTest`、`AdminOrderListIntegrationTest`、`LegacyAdminRbacIntegrationTest`、`OrderListOwnedIntegrationTest`），重写 `ClientIpResolverTest`（2→4 例）。

## 三、验证结果

- 单元测试：**240/240**（原 231 + 安全守卫 7 + IP 解析净增 2），0 skipped。
- 集成测试：**100/100**（原 93 + 7：参数错误契约 4、运营订单标题 1、权限降权 1、订单列表 owned 1）。
- 定向复跑：SUPER_ADMIN 门禁版 `LegacyAdminRbacIntegrationTest` 1/1 通过。
- 静态校验：`compose.yml` YAML 解析通过；`btry-backup.sh` / `setup-server.sh` `bash -n` 通过；`start-local.ps1` / `backup-mysql.ps1` PowerShell 解析通过。
- CI：提交后由 frontend / backend / docker-build 三任务复验。

## 四、剩余观察项（本轮未改，附理由）

1. `PaymentService.pay()` 在事务内调用渠道下单、持订单行锁跨网络：改动事务边界风险高，需单独设计与压测，故不在本轮动刀。
2. 退款渠道调用与租约：超时后租约到期可被再次调用，依赖支付宝 `out_request_no` 幂等兜底；单实例部署可接受。
3. Outbox 无 `SKIP LOCKED`：当前单实例运行，多实例前需补。
4. `t_recon_break` 无 `(run_id,item_id)` 唯一键：需先清洗存量重复差异再迁移。
5. ngram 单字搜索为空：需调整分词/索引策略，属检索体验优化。
6. 课程教师端点仍按 legacy `TEACHER`：邀请开通的教师尚无 RBAC OPERATOR，直接迁移会改变访问集合，需与课程模块退役一并处理。
7. 前端运营路由仍按 legacy 角色门控（后端已 RBAC 校权）：属 UX 门控，安全由后端兜底，待前端与 RBAC 统一。

## 五、结论

审查中的 BLOCKER 与全部 MAJOR 已闭环，MINOR 已修复或给出可执行结论；门禁与 CI 配置同步加固。项目达到「可部署、可回滚、权限可撤销、支付不可旁路、错误码可预期」的生产工程基线。
