# btry 上云与后续演进计划

更新日期：2026-11-02

状态：**计划文档，尚未执行上云操作**

## 1. 目标与边界

将当前单机录播学习平台部署为云上的内部生产系统，目标是：

- 可重复部署；
- 可监控、可追踪；
- 可备份、可恢复；
- 可安全发布和回滚；
- 出现问题时有明确处置步骤。

目标形态：

- Linux 云主机承载 Spring Boot API。
- Caddy 提供 HTTPS、前端静态文件和 `/api` 反向代理。
- MySQL 8 保存业务与日志数据。
- Redis 7 承担 URL 缓存、登录限流、幂等和告警去重。
- COS 保存视频对象和数据库备份。
- 视频由浏览器直连 COS，不经过应用主机转发。
- 仍然保持单体应用，不引入 Kubernetes、CDN、MQ 和完整 RBAC。

云厂商默认按腾讯云规划，因为现有 COS 已在腾讯云；云主机与 COS 保持同地域。具体机型不绑定，初始建议：

- 2 vCPU / 4GB 内存；
- 80GB SSD；
- Ubuntu 24.04 LTS；
- 公网或内网访问方式在阶段 0 确认。

## 2. 阶段 0：上云前决策

### 2.1 访问方式

必须先确定一种：

1. 公网域名访问：需要域名、DNS 和 TLS；如使用中国大陆地域，域名备案是前置条件。
2. 内网/VPN 访问：不直接暴露公网 API，使用内部 DNS 和内部证书或受控证书方案。
3. 公网管理入口 + 内网业务入口：适合管理员远程维护，但需要额外的访问控制。

### 2.2 云资源清单

- 1 台云主机；
- 1 个域名或内部 DNS 记录；
- 现有 COS 视频桶；
- 独立备份桶或独立备份前缀；
- 云防火墙/安全组；
- 可选：云监控、快照策略、对象存储版本控制。

### 2.3 账号与权限

- SSH 使用密钥，禁用 root 远程登录和密码登录。
- 创建独立部署账号 `btry`。
- MySQL 使用独立业务账号，不使用 root。
- Redis 设置密码并限制监听地址。
- COS 使用最小权限子账号，禁用主账号密钥。
- 生产凭据不进入 Git、镜像、日志或前端构建产物。

### 2.4 回滚准备

- 保留当前本地运行环境和完整数据库备份。
- 记录当前 Flyway 版本、账号清单和 COS 对象键。
- 准备旧环境回滚步骤。
- 云环境稳定运行至少两周后再清理旧环境。

阶段验收：访问方式、服务器规格、域名、备份位置、账号权限和回滚环境全部明确。

## 3. 阶段 1：云主机基础环境

### 3.1 系统初始化

- 更新系统安全补丁。
- 设置时区为 `Asia/Shanghai`。
- 配置 NTP 时间同步。
- 安装 Java 17、MySQL 8、Redis 7、Caddy、MySQL 客户端和基础运维工具。
- 配置 SSH 安全组，只允许管理员来源访问。
- 为部署账号配置最小 sudo 权限。

### 3.2 目录规划

```text
/opt/btry/app         后端 jar
/opt/btry/web         前端 dist
/etc/btry             环境变量和 Caddy 配置
/var/log/btry         应用日志
/var/backups/btry     MySQL 本地备份
```

### 3.3 应用运行

- 后端使用 `systemd` 管理。
- 使用 `prod` profile。
- 关键变量缺失时允许应用启动失败，不提供生产默认密钥。
- 开启优雅停机、自动重启和开机自启。
- Caddy 提供 HTTPS、SPA 路由回退和 API 反向代理。
- 配置日志轮转、最大文件大小和保留周期。

阶段验收：机器重启后服务自动恢复；健康检查正常；日志和配置目录权限正确。

## 4. 阶段 2：数据迁移与切换

### 4.1 迁移步骤

1. 在本地执行 MySQL 全量备份。
2. 通过受控通道上传备份到云主机。
3. 在云 MySQL 恢复。
4. 核对 Flyway schema version。
5. 核对用户、系列、章节、视频和学员系列关系。
6. 核对播放日志和管理员审计记录。
7. Redis 不迁移，URL 缓存重新生成。

### 4.2 预验收

在正式切换前使用临时域名、临时端口或 hosts 映射完成：

- 管理员登录；
- 学员登录；
- 学习空间；
- 系列详情；
- 视频播放；
- 管理页；
- 日志、指标和告警。

### 4.3 正式切换

1. 提前调低 DNS TTL。
2. 设置维护窗口并停止旧环境写入。
3. 执行最终数据库备份。
4. 恢复云数据库。
5. 启动云服务。
6. 执行冒烟测试。
7. 切换 DNS 或访问入口。
8. 观察错误日志、告警和登录情况。

### 4.4 回滚

- 保留旧数据库和旧应用目录。
- 切换失败时恢复 DNS 或访问入口。
- 重新启动旧环境。
- 回滚前确认云环境没有产生无法合并的新业务数据；如已产生新数据，需要单独导出。

阶段验收：管理员和学员均可在云环境登录；视频播放地址来自 COS；审计和播放日志正常入库。

## 5. 阶段 3：安全收口

- 仅启用 `prod` profile。
- Caddy 负责 TLS；应用检测到安全请求时返回 HSTS。
- `TRUST_FORWARDED_HEADERS=true` 只在 Caddy 会覆盖转发头时启用。
- CORS 白名单改为真实域名，不使用通配符。
- Actuator 只监听 `127.0.0.1`，不直接暴露公网。
- 管理员首次登录必须改密。
- 停用演示账号和临时验收账号，保留生产账号清单。
- 登录限流、密码策略、审计目标 ID、traceId 在云环境重新验证。
- 备份目录不可被 Caddy 静态文件服务访问。
- 安全响应头、错误信息和日志脱敏重新检查。

阶段验收：未知来源 CORS 被拒绝；普通学员不能访问管理接口；生产环境不存在默认密钥；安全响应头完整。

## 6. 阶段 4：备份、监控与告警

### 6.1 备份

- 每日执行 MySQL 全量备份。
- 发布前额外备份。
- 本地备份与 COS 独立备份前缀双份保存。
- 建议保留 30 天。
- 备份文件设置最小权限。
- 使用 systemd timer 或 cron 定时执行。

### 6.2 恢复演练

- 每周至少抽查一次备份完整性。
- 每月至少完成一次恢复演练。
- 恢复到临时数据库，不覆盖生产库。
- 验证账号、系列、视频关系、日志和 Flyway 版本。

### 6.3 监控与告警

基线监控：

- Actuator health；
- Prometheus 指标端点；
- 应用日志；
- MySQL 连接池；
- 磁盘、内存和进程状态；
- 登录限流；
- 播放错误、卡顿和缓存命中；
- 日志队列丢弃和熔断状态。

告警：

- 告警写入 `t_alert_log`；
- 配置真实 `ALERT_WEBHOOK_URL` 后外部推送；
- 定期检查 `delivered` 和 `delivery_error`。

Prometheus/Grafana 作为增强项，不阻塞首次上云。只有现有指标、日志和告警不足以定位问题时再引入。

阶段验收：备份实际生成；至少完成一次恢复演练；告警能从数据库和 webhook 两条路径确认。

## 7. 阶段 5：上线验收

- 服务健康、liveness、readiness 正常。
- 管理员登录、建号、改密、启停、重置密码、系列分配正常。
- 学员登录、学习空间、系列详情、切换课时正常。
- 浏览器可直接播放 COS 视频。
- 通过 `X-Trace-Id` 能串联应用日志、播放日志和审计日志。
- 审计包含操作人、目标用户 ID、traceId 和执行结果。
- 弱密码被拒绝；连续失败触发限流。
- CORS、安全响应头、HTTPS 和静态资源访问正常。
- 后端测试、前端构建和 CI 通过。
- 回滚步骤已演练。

## 8. 上线后 0～7 天

- 每天检查服务日志、错误日志、告警记录和磁盘。
- 每天确认备份成功。
- 观察登录失败、播放错误、缓存命中率和数据库连接池。
- 不新增业务功能，只修上线暴露的问题。
- 完成一次真实恢复演练。
- 记录实际资源占用，作为后续容量判断依据。
- 保持旧环境可回滚。

## 9. 上线后 30 天

- 建立固定运维节奏：
  - 每日检查 health 和备份；
  - 每周检查错误趋势和磁盘；
  - 每月抽查恢复。
- 根据实际排障需要决定是否部署 Prometheus/Grafana。
- 根据日志量决定是否引入集中日志。
- 清理测试账号和无效数据。
- 固化发布、回滚和故障处理手册。
- 评估是否需要云托管 MySQL/Redis；只有对可用性、自动备份或运维责任有明确要求时再做。

## 10. 后续技术触发条件

- **托管 MySQL/Redis**：需要更高可用性、自动备份或减少自维护责任时。
- **MQ**：出现多实例、日志不能丢失或异步任务跨节点时。
- **完整 RBAC**：出现同角色内部权限差异、资源级授权或多管理边界时。
- **Prometheus/Grafana**：Actuator、日志和数据库告警不足以定位问题时。
- **集中日志**：单机日志检索明显影响排障时。
- **40 分钟视频测试**：放在云环境稳定后的最后阶段，使用真实长视频单独验证。

## 11. 交付物

上云执行时需要形成以下文件：

- 生产环境变量模板；
- `systemd` 服务单元；
- Caddy 生产配置；
- 数据迁移和恢复清单；
- 备份定时任务与恢复演练脚本；
- 上线检查表和回滚手册；
- 云账号、端口、权限和资源清单。

## 12. 执行顺序

建议按以下顺序推进：

1. 完成阶段 0 的访问方式、域名和资源确认。
2. 完成阶段 1 的云主机基础环境。
3. 完成阶段 2 的首次迁移和可回滚上线。
4. 立即补阶段 3 的生产安全收口。
5. 完成阶段 4 的备份、恢复演练和告警验证。
6. 执行阶段 5 的全量验收。
7. 进入上线后 0～7 天和 30 天运维节奏。
8. 最后才安排 40 分钟真实长视频测试。

Prometheus/Grafana、MQ、RBAC 和长视频测试都不作为首次上云的前置条件。
