# 模块解耦实施清单

更新日期：2026-11-05

目标：在单 Spring Boot 应用内建立稳定的模块契约，降低跨模块直接依赖，不改变现有 API、数据库和业务行为。

## 第一阶段：基础契约

- [x] 盘点跨模块依赖
- [x] 建立 `commerce -> platform.alert` 的 `AlertPublisher` 端口
- [x] 支付确认、退款、履约不再直接依赖 `AlertLogRepository`
- [x] 建立 `learning.api.PlaybackUrlProvider`
- [x] 建立 `learning.api.PlaybackEventPublisher`
- [x] 课程播放服务不再依赖 `PlaybackUrlCache` 和 `PlaybackLogService` 实现
- [x] 建立 `commerce.api.AdminOrderOperations` 管理员订单门面
- [x] `operations.admin` 不再直接使用订单/支付 Repository 和补偿服务
- [x] 新增 ArchUnit 模块边界测试

## 第二阶段：继续收口

- [x] 为 `identity` 建立账号操作应用契约，运营端不再直接使用用户 Repository
- [x] 为 `course` 建立课程治理应用契约，运营端不再直接依赖课程 Mapper
- [x] 将订单状态转换规则收敛到 `OrderTransitionPolicy`
- [x] 评估支付渠道注册表：暂不引入；当前只有 Mock 和支付宝，Spring 条件 Bean 已足够
- [x] commerce 订单边界：退款终态释放 active_key、过期 PAYING + 支付宝交易不存在安全关闭、终态支付尝试不复用、REFUND_FAILED 不允许普通关单
- [x] 退款失败有界自动重试：尝试次数、退避时间、最大次数和补偿任务重新调度
- [ ] 为非资金副作用引入进程内领域事件
- [ ] 评估是否需要事务性 outbox，暂不引入 MQ

## 上线前可靠性收口

- [x] 移除登录页旧演示口令
- [x] 支付宝回调请求体上限 64KB
- [x] 支付告警巡检：已支付未履约、支付中堆积、退款重试耗尽
- [x] 管理员订单页展示退款尝试次数和下次重试时间
- [x] 修复 Redis 播放 URL 的本地新鲜期计算
- [x] 增加 Linux 数据库备份脚本、systemd timer 和日志轮转配置
- [ ] 真实生产支付宝支付与退款验收
- [ ] 浏览器 E2E 自动化（当前本地未安装 Playwright，暂未引入）

## 第三阶段：逐模块优化

- [x] `commerce`：订单、支付、退款、补偿的边界修复与可靠性收口
- [x] `learning`：播放 URL 缓存新鲜期修复与回归测试
- [x] `course`：课程治理契约收口与运营端解耦
- [x] `identity`：账号操作契约收口与运营端解耦
- [x] `operations/platform`：支付告警、备份 timer 和日志轮转
- [x] 前端按 feature 重新组织，并保持现有路由和交互
