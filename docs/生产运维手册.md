# btry 生产运维手册

更新日期：2026-11-05

## 1. 当前部署定位

- 单体 Spring Boot 应用。
- MySQL 保存账号、系列、播放日志和审计。
- Redis 保存播放 URL 缓存、限流、幂等和告警去重。
- COS 直接提供视频对象，不经过应用服务器转发视频。
- 单机部署，不引入 CDN、HLS、MQ、微服务。

本手册的目标是让单机环境可重复部署、可排障、可恢复，而不是把系统改造成分布式架构。

## 2. 生产环境变量

生产启动必须使用 `prod` profile，并设置以下配置：

| 变量 | 必填 | 说明 |
|---|---|---|
| `DB_URL` | 是 | MySQL JDBC URL |
| `DB_USER` / `DB_PASSWORD` | 是 | MySQL 账号 |
| `REDIS_HOST` / `REDIS_PORT` | 是 | Redis 地址 |
| `REDIS_PASSWORD` | 是 | 生产 Redis 密码 |
| `JWT_SECRET` | 是 | 至少 32 字节，必须随机生成 |
| `CORS_ALLOWED_ORIGINS` | 是 | 前端实际访问源，逗号分隔 |
| `COS_BUCKET` / `COS_REGION` | 是 | COS 桶和地域 |
| `COS_SECRET_ID` / `COS_SECRET_KEY` | 是 | COS 凭据 |
| `SAMPLE_VIDEO_KEY` | 是 | 当前演示视频或正式视频对象键 |
| `APP_BASE_URL` | 是 | 教师邀请链接使用的前端地址 |
| `TEACHER_INVITE_EXPIRY_HOURS` | 否 | 教师邀请有效期，默认 72 小时 |
| `TEACHER_INVITE_MAX_ATTEMPTS` / `TEACHER_INVITE_WINDOW_MINUTES` | 否 | 邀请公开接口 IP 限流 |
| `UPLOAD_MAX_SIZE_BYTES` | 否 | 单个视频最大字节数 |
| `UPLOAD_URL_TTL_MINUTES` | 否 | COS 上传地址有效期 |
| `UPLOAD_ALLOWED_CONTENT_TYPES` | 否 | 允许的 MIME 类型 |
| `SEED_ADMIN_PASSWORD` / `SEED_TEACHER_PASSWORD` / `SEED_STUDENT_PASSWORD` | 否 | 首次启动创建演示账号的初始密码；留空则随机生成并在日志打印一次，三个账号都强制首次改密。账号已存在时不会重置 |
| `PAYMENT_PROVIDER` | 是 | `mock` / `alipay`，生产必须 `alipay`，禁止 Mock |
| `ALIPAY_APP_ID` | 是（alipay） | 开放平台应用 ID |
| `ALIPAY_PRIVATE_KEY` | 是（alipay） | 应用私钥，PKCS8 纯 Base64，一行、不带头尾 |
| `ALIPAY_PUBLIC_KEY` | 是（alipay） | 支付宝公钥（不是应用公钥），用于回调验签 |
| `ALIPAY_SELLER_ID` | 否 | 商家 PID，配置后回调校验 seller_id，留空跳过该项 |
| `ALIPAY_GATEWAY_URL` | 是（alipay） | 生产 `https://openapi.alipay.com/gateway.do` |
| `ALIPAY_NOTIFY_URL` | 是（alipay） | 公网 HTTPS 异步通知地址，需在 JwtAuthFilter 白名单内 |
| `ALIPAY_RETURN_URL` | 是（alipay） | 支付完成回跳地址，网关再拼 `/订单号` |
| `PAYMENT_ORDER_EXPIRE_MINUTES` | 否 | 订单支付有效期，默认 15 分钟 |
| `PAYMENT_QUERY_AFTER_SECONDS` | 否 | 支付中订单进入主动查单的等待时间 |
| `PAYMENT_RECONCILE_INTERVAL_MS` | 否 | 支付补偿任务执行间隔 |
| `PAYMENT_REFUND_MAX_ATTEMPTS` | 否 | 退款失败自动重试最大次数，默认 5 |
| `PAYMENT_REFUND_RETRY_BASE_SECONDS` | 否 | 退款重试基础退避秒数，默认 30 |
| `LOG_FILE` | 否 | 日志路径，默认 `logs/btry-prod.log` |
| `ALERT_WEBHOOK_URL` | 否 | 告警 webhook；留空时只入库 |
| `TRUST_FORWARDED_HEADERS` | 否 | 只有反向代理会覆盖转发头时才设为 `true` |

`application-prod.yml` 对关键变量不提供默认值，缺配置会直接启动失败。这是有意的 fail-fast，避免误用开发密钥或默认数据库。

## 3. 构建与启动

构建后端：

```powershell
cd server
mvn -q -DskipTests package
```

构建前端：

```powershell
cd web
npm ci
npm run build
```

启动后端：

```powershell
$env:SPRING_PROFILES_ACTIVE = 'prod'
java -jar server\target\btry-0.1.0.jar
```

生产环境不要让终端窗口承担进程守护职责。使用 WinSW、NSSM 或 Windows 任务计划程序配置：

- 开机自动启动；
- 异常退出自动重启；
- 标准输出和错误输出写入独立文件；
- 运行账号只拥有应用目录、日志目录和备份目录所需权限。

### 3.1 当前生产部署（Linux + systemd）

生产跑在腾讯云 Ubuntu 上，域名 `whereri.site`，课程演示挂在 `/learn/` 子路径，与个人作品集共用一个证书和 server 块。

- 应用目录 `/opt/btry`，jar 为 `/opt/btry/btry.jar`，环境变量文件 `/opt/btry/.env`（权限 600，不进仓库）。
- `deploy/btry.service` 以 `ubuntu` 账号运行，`EnvironmentFile=/opt/btry/.env`，`SPRING_PROFILES_ACTIVE=prod`，异常退出自动重启，stdout/stderr 写 `/opt/btry/logs/`。
- MySQL 8 与 Redis 7 由 systemd 托管并开机自启；Redis 只绑 127.0.0.1 且启用 requirepass。
- 一键部署：`pwsh tools/deploy-prod.ps1`。它构建 jar 与 `base=/learn/` 的前端、生成随机 DB/Redis/JWT 密钥、从本机 `server/.env` 与 `~/.cos.conf` 组装生产 env、上传产物并执行 `deploy/setup-server.sh`。脚本幂等，重复执行只更新产物与密码，不会重复导入演示数据。
- `deploy/setup-server.sh` 负责建库建用户、首次导入 `backups/` 里最新的演示数据、安装 systemd 单元与 nginx 片段、reload nginx 并重启应用。
- 换行符红线：Windows 生成的 env 文件必须是 LF。CRLF 会让 bash source 把 `\r` 带进密码，而 systemd EnvironmentFile 会剥掉它，两边不一致就出现 MySQL/Redis 认证失败。排查时用 `cat -A` 看值尾部有没有 `^M`。

## 4. 反向代理与访问控制

前端构建产物由反向代理提供，API 转发到 `127.0.0.1:8084`。

当前生产用 nginx：站点配置 `/etc/nginx/sites-available/whereri.site`，课程相关片段由 `deploy/nginx-learn.conf` 安装到 `/etc/nginx/snippets/btry-learn.conf` 并 include 进 443 server 块。

- `location /learn/`：Vue SPA，`try_files $uri $uri/ /learn/index.html`，HTML 不缓存；
- `location /api/`：反代 8084，`X-Forwarded-For` 用 `$remote_addr` 覆盖而不是追加；
- `/learn/` 的 CSP 在个人站基础上放开 `media-src` / `connect-src` 的 `https://*.myqcloud.com`，否则 COS 视频播不了；该 location 内重写了整套安全头，因为 nginx 的 `add_header` 不与上级叠加；
- 支付宝收银台是整页 GET 跳转，不受 `form-action 'self'` 影响；不要改成自提交表单。

`deploy/Caddyfile.example` 保留为另一种单机示例。上线前需要修改：

- 站点地址；
- 前端 `dist` 绝对路径；
- 是否启用 HTTPS；
- 内网来源限制。

如果设置 `TRUST_FORWARDED_HEADERS=true`，必须确保反向代理覆盖客户端传入的 `X-Forwarded-For` 和 `X-Real-IP`，否则客户端可以伪造 IP，绕过登录限流。

Actuator 默认只监听 `127.0.0.1:9091`，不应直接暴露到公网。

## 5. 日志与 traceId

- 后端日志默认写入 `logs/btry-prod.log`。
- `stdout.log` / `stderr.log` 由 `/etc/logrotate.d/btry` 每日轮转，保留 14 天并压缩。
- 单文件最大 20MB，保留 14 天，总容量上限 1GB。
- 每个请求生成 `X-Trace-Id`，响应头返回该值。
- 播放日志和审计日志会把 `trace_id` 入库。
- 日志级别格式包含 `traceId=%X{traceId:-}`，同一请求可串联应用日志。

排查顺序：

1. 从浏览器响应头获取 `X-Trace-Id`。
2. 在应用日志中搜索该 traceId。
3. 查询 `t_playback_log` 或 `t_admin_audit_log` 的 `trace_id`。
4. 如果涉及视频，继续检查 COS 预签名、URL 缓存命中和浏览器 Network。

## 6. 安全基线

- 管理账号只能由管理员创建，不开放自助注册。
- 新账号和重置密码后的账号必须首次改密。
- 密码要求 8-32 位，同时包含字母和数字，并拒绝常见弱密码。
- 登录按“用户名 + IP”限流，默认 10 分钟 8 次失败。
- 同一 IP 跨用户名默认 10 分钟最多 40 次失败。
- 禁用账号、重置密码、用户改密都会使旧 token 失效。
- 管理员不能禁用或重置自己。
- 生产必须关闭开发默认 JWT 密钥。
- 反向代理负责 HTTPS 时，应用检测到安全请求后补充 HSTS。

## 7. 监控与告警

健康检查：

```text
http://127.0.0.1:9091/actuator/health
```

Prometheus 指标：

```text
http://127.0.0.1:9091/actuator/prometheus
```

重点指标：

- `security.login.blocked`
- `playback.url.cache`
- `playback.log.dropped`
- `playback.log.persist.errors`
- `playback.audit.failures`
- `btry.method`
- Hikari 连接池指标

告警写入 `t_alert_log`。配置 `ALERT_WEBHOOK_URL` 后才会外部推送；未配置时 `delivered=0` 且 `delivery_error` 会记录原因。

当前告警类型包括播放错误、播放卡顿、URL 缓存未命中、日志队列丢弃、熔断打开和登录限流触发（`LOGIN_BLOCKED`）。

## 8. 备份

生产环境通过 `btry-backup.timer` 每日 02:30 执行 `btry-backup.sh`，备份写入 `/opt/btry/backups`，默认保留 14 天。也可以手工执行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File tools\backup-mysql.ps1
```

建议在以下时点额外备份：

- 发布前；
- 批量导入账号或系列前；
- Flyway 迁移前。

备份文件默认写入 `backups/`，需要纳入独立磁盘或受控备份目录，不能只留在应用所在磁盘。

## 9. 恢复演练

恢复是覆盖操作，必须显式传入 `-Force`：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File tools\restore-mysql.ps1 `
  -BackupFile "C:\backups\btry_edu-20261102-030000.sql" `
  -Database btry_edu `
  -Force
```

至少验证：

- 账号数量正确；
- 系列、章节、视频关系完整；
- 学员系列分配正确；
- 管理员可以登录；
- 学习空间和播放页可用；
- Flyway 版本与代码匹配。

当前最低恢复目标是每日全量备份、RPO 约 24 小时。若无法接受，需要增加 binlog 或更频繁备份。

## 10. 故障处置

### MySQL 不可用

- 健康检查 `db` 组件会失败；
- 登录、系列和管理接口不可用；
- 首先确认 MySQL 服务和磁盘；
- 恢复后检查 Flyway 版本和连接池是否恢复。

### Redis 不可用

- 视频 URL 缓存降级为本地生成，仍可播放；
- 登录、公开接口和通用限流切换 Caffeine 本地固定窗口，超限仍返回 429；
- 幂等切换本地 TTL 缓存，资金唯一性继续由 MySQL 约束保证；
- 告警去重切换本地缓存，极端情况下可能重复告警；
- readiness 不依赖 Redis，整机仍可提供业务能力；整体 health 会显示 Redis 组件异常；
- 观察 `infra.redis.fallback` 按组件统计降级次数；
- 恢复后确认 Redis 连接和 key TTL。

完整策略见 `docs/Redis降级与MQ边界.md`。

### COS 不可用或凭据错误

- 播放 URL 获取失败，已缓存 URL 在有效期内仍可能可用；
- 检查 COS 凭据、桶、地域、对象键和网络；
- 不要把 COS 临时故障误判为播放器问题。

### 支付成功但权益未发放

- 订单应停留在 `PAID`，而不是直接丢失；
- 查看 `payment.fulfillment.failed`、订单 `last_error` 和 `t_alert_log`；
- 补偿任务会重试，管理员也可以在订单详情点击“补履约”；
- 补履约使用权益唯一键，不会重复发放；
- 不要通过手工修改 `t_order.status` 绕过支付事件和审计。

### 支付回调丢失或超时

- 查看 `payment.callback.*`、订单支付尝试和支付事件；
- 管理员先执行“主动查单”，再决定补履约或关单；
- `PAYING` 订单不允许直接关闭，避免误关已扣款订单；
- 金额不一致必须人工核对，不能自动发货。
- 支付宝回调验签失败返回 `failure` 并触发重投：先确认 `ALIPAY_PUBLIC_KEY` 是支付宝公钥而不是应用公钥，再确认报文 charset 与解码一致；
- 回调按报文自带 charset 解原始字节验签，不依赖容器默认编码（支付宝网关可能返回 GBK）；
- `notify_id` 是幂等键，重复通知返回 success 但不会重复发货；
- 退款返回 `fund_change=N` 时会再查退款单确认，未确认按失败处理并由补偿任务重试。

### 日志队列积压

- 查看 `playback.log.queue.size` 和 `playback.log.dropped`；
- 检查 MySQL 写入错误；
- 单实例队列没有持久化，进程退出会丢失尚未写入的事件，这是当前明确限制。

### 磁盘空间不足

- 检查日志滚动和备份保留；
- 不要直接删除正在使用的数据库文件；
- 清理前先确认备份可用。

## 11. 发布与回滚

发布前：

1. 执行 `tools\verify.ps1`；
2. 备份数据库；
3. 确认生产环境变量；
4. 构建后端和前端；
5. 检查 Flyway 迁移内容。

发布后：

1. 检查 `/actuator/health`；
2. 登录管理员和学员账号；
3. 打开学习空间和系列播放页；
4. 检查错误日志和告警。

回滚需要同时考虑应用版本和数据库迁移。Flyway 迁移默认不做自动回退，数据库结构变更前必须备份，并准备好人工回滚 SQL。

## 12. 当前明确限制

- 单实例部署，没有多副本协调。
- 播放日志队列在进程内存中。
- 没有 MQ。
- 没有完整 RBAC。
- 支付已接入支付宝电脑网站支付（个人账号、无营业执照档：单笔 ≤50 元、单日 ≤1000 元）；微信支付未接入。
- 支付宝服务费 0.6%，单笔四舍五入保留两位小数；电脑网站支付退款时手续费不退回。演示价 0.01 元的服务费四舍五入为 0。
- 支付补偿任务按单实例设计，多副本前必须增加任务锁。
- 退款只支持管理员发起全额退款。
- Prometheus/Grafana/Jaeger 目前是 staging 可选 profile，生产 systemd 尚未接入。
- 40 分钟真实长视频压测暂缓。
- COS 对象仍需要人工准备和校验。
