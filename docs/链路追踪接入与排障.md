# 链路追踪接入与排障

更新日期：2026-11-05

## 1. 方案

使用 Spring Boot 原生 Micrometer Tracing + OpenTelemetry OTLP：

- `io.micrometer:micrometer-tracing-bridge-otel`
- `io.opentelemetry:opentelemetry-exporter-otlp`
- Jaeger all-in-one 作为 staging 的 OTLP 接收端和查询 UI

生产默认关闭；staging 通过环境变量开启。

## 2. 配置

```text
TRACING_ENABLED=true
OTLP_TRACING_ENDPOINT=http://jaeger:4318/v1/traces
TRACING_SAMPLING_PROBABILITY=1.0
```

对应 `application.yml`：

```yaml
management:
  tracing:
    enabled: ${TRACING_ENABLED:false}
    sampling:
      probability: ${TRACING_SAMPLING_PROBABILITY:0.1}
  otlp:
    tracing:
      endpoint: ${OTLP_TRACING_ENDPOINT:http://127.0.0.1:4318/v1/traces}
```

生产建议采样 0.1，并只在有 collector 时开启；staging 用 1.0 便于验收。

## 3. 埋点位置

| span | 位置 | 关键标签 |
|---|---|---|
| `payment.confirm` | `PaymentService.acceptVerified` | `order.no`、`payment.provider`、`payment.event.type` |
| `payment.gateway.initiate` | 支付发起 | `order.no`、`payment.channel` |
| `payment.gateway.query` | 主动查单 | `order.no`、`payment.channel` |
| `payment.refund` | `RefundService.processRefund` | `order.no`、`refund.no`、`refund.simulate_failure` |
| `order.fulfill` | `OrderFulfillmentService.fulfill` | `order.no` |
| `payment.callback.alipay` | `AlipayNotifyService.handle` | `payment.provider` |
| `payment.reconcile.job` | `PaymentReconciliationJob.run` | 无 |
| `playback.url.resolve` | `CachedPlaybackUrlProvider.get` | `video.key`、`cache.hit` |

HTTP、JDBC、Redis 由 Spring Boot/OpenTelemetry 自动 instrumentation 覆盖。

## 4. traceId 关联

`TraceIdFilter` 现在优先读取当前 span 的 traceId，而不是无条件生成 UUID；因此：

- 响应头 `X-Trace-Id`；
- 日志 MDC `traceId`；
- Jaeger traceId；
- span 标签 `btry.trace_id`；

四者一致。若 tracing 关闭，仍回退到原来的 16 位 UUID。

## 7. 注意

- 不要把 Jaeger UI 暴露到公网；
- 不要在 span 标签里写密钥、完整回调报文或手机号；
- 单服务场景下 tracing 的主要价值是外部调用、补偿任务和日志关联，不是展示“微服务链路”；
- 短生命周期测试进程退出时 batch exporter 可能来不及 flush，业务 span 应在长期运行的应用上验收；
- 如果后续需要 tail sampling、长期存储或跨服务传播，再引入 Collector/Tempo，不要现在增加运维负担。
