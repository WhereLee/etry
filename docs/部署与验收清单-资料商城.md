## 2. 生产配置核查（application-prod.yml）

- **无默认密钥**：`DB_URL/DB_USER/DB_PASSWORD/REDIS_PASSWORD/JWT_SECRET/CORS_ALLOWED_ORIGINS/ALIPAY_*` 均为必填环境变量，缺失则启动失败，不提供生产默认值。
- **Actuator 不暴露公网**：`management.server.address: 127.0.0.1`，`health.show-details: never`。
- **CORS 白名单**：生产由 `CORS_ALLOWED_ORIGINS` 注入真实域名，不用通配符。
- **登录保护**：`login-protection-enabled: true`，账号/IP 双维度限流。
- **种子密码**：`SEED_ADMIN_PASSWORD` 留空则首次启动随机生成并打印一次，账号已存在不重置；演示账号首次登录强制改密。
- **支付（fail-closed）**：Mock 支付默认关闭；`provider=mock` 且未显式 `PAYMENT_MOCK_ENABLED=true` 时应用启动失败。prod profile 一律禁止 Mock；真实支付宝需注入商户密钥。
- **API 文档**：prod 关闭 springdoc（`api-docs`/`swagger-ui` 均 false），避免生产暴露接口清单。
- **转发头**：`TRUST_FORWARDED_HEADERS` 默认 false，仅在边缘代理**覆盖**（而非追加）`X-Forwarded-For` 时启用；nginx 示例见 `web/nginx.conf` 与 `deploy/nginx-learn.conf`。

## 4. 云上验收清单（待外部输入后执行）

外部输入（用户需提供）：
- 域名 + DNS（中国大陆地域需备案）；
- 云主机 SSH（密钥登录，独立部署账号）；
- 支付宝商户号（沙箱即可）用于 ¥0.01 真实支付验收。

执行步骤：
1. 云主机初始化（`setup-server.sh`），时区 Asia/Shanghai，NTP，安全组只放行 80/443 与受限 SSH。
2. 注入生产环境变量（真实域名 CORS、强随机 JWT_SECRET、独立 MySQL 业务账号、Redis 密码、支付宝密钥）；缺失关键变量应用应启动失败。
3. 恢复本地 MySQL 全量备份，核对 Flyway 版本（当前 V24）与账号/资料/订单/权益/审计数据。
4. systemd 启动 backend（prod），Caddy 提供 HTTPS 与反代；机器重启后服务自动恢复。
5. 预验收（临时域名/hosts）：买家注册→浏览资料→加购→结算→支付→履约→书架试读/下载；运营资料 CRUD/上传/上下架；客服退款申请处理；财务对账导出；审计日志。
6. 安全收口复验：未知来源 CORS 拒绝、学员访问管理接口 403、生产无默认密钥、安全头完整、Actuator 仅 127.0.0.1、备份目录不被静态服务访问。
7. 真实支付验收：支付宝沙箱 ¥0.01 下单→扫码支付→异步通知→履约→退款原路退回。
8. 备份/恢复演练：每日备份实际生成（MySQL dump + materials tar.gz），恢复到临时库并解压资料目录，核对 Flyway 与关键表、抽查已上传 PDF 可下载。
9. 监控告警：health/readiness/liveness、Prometheus 指标、`t_alert_log` 与 webhook 双路径。
10. 回滚演练：保留旧库与旧 jar，切换失败可恢复 DNS 与旧环境。

## 5. 已知边界

- 本机无 Docker，compose 构建在 CI 的 docker-build job 验证（已通过）；本地以原生 MySQL/Redis + jar 验证。
- 资料 PDF 当前走本地磁盘持久卷；如需对象存储/CDN，按触发条件再切换（不影响权益门槛与水印逻辑）。
- 真实支付宝在商户号接入前保持 mock；mock 全链路已由集成测试与冒烟覆盖。
