# 阶段2总结：数据模型与契约

## 一、本阶段做了什么
- 包根重命名 com.wherelee.edu → com.wherelee.material（272 个 Java 文件 + mapper XML + 3 个 yml），EduApplication → MaterialApplication；修复守卫中转义/斜杠变体残留
- V21 迁移：
  - t_material 资料目录（分类/学段/学科/价格/试读页数/文件键/上架状态 + ngram 全文索引）
  - t_cart_item 购物车（唯一 user_id+material_id，数量恒 1 不建数量列）
  - t_order_item 订单明细（标题/价格快照，唯一 order_id+material_id）
  - t_order 单商品列放宽可空（购物车订单总额语义，旧数据不变）
  - RBAC 四表 t_role/t_permission/t_role_permission/t_user_role，预置 5 角色（BUYER=SELF 数据范围，其余 ALL）
- material 模块：MaterialRecord/MaterialRepository（CRUD+全文检索）、MaterialSellableCatalog（可售门槛：上架+定价+已挂文件）、api.MaterialQuery 跨模块读端口
- commerce：CartRepository（幂等加购/结算移除）、OrderItemRepository（批量快照写入）
- identity：RbacRepository（角色/权限点/授权链路，幂等 grant/link）
- ArchUnit：新增 material 模块边界规则 2 条 + 既有规则纳入 material；TableOwnership 登记 7 张新表归属
- 默认值声明（用户未给数字，按推荐落地）：试读页数默认 3；资料文件计划存本地磁盘（存储实现留待履约阶段，本阶段未写存储代码）

## 二、验证结果
- 单元测试: 173/173 通过（含新增边界规则）
- 集成测试: 48/48 通过（新增 6：目录全文检索、可售门槛、购物车 8 线程并发幂等、明细快照唯一约束、RBAC 授权链路、读端口事实）
- 并发验证: 8 线程同时加购同一资料 → 恰 1 行（唯一约束兜底，INSERT IGNORE 幂等）
- 接口冒烟（btry_smoke）: health 200、登录/me 200、无 token 401 不变；V21 在运行库落地，5 预置角色正确
