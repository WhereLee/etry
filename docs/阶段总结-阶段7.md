# 阶段7总结：质量 / 安全 / 部署准备

## 一、本阶段做了什么

本阶段不新增业务功能，聚焦把资料商城推到「可部署、可验收、安全收口」状态。

### 1. 安全收口验证（对运行中的 8084 实测）
- 安全响应头：`Content-Security-Policy`（default-src 'self'）、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Permissions-Policy` 五项齐全；HSTS 仅在 HTTPS 请求下发（本地 http 正确缺席）。
- CORS：未知来源 `https://evil.example` 不回显 `Access-Control-Allow-Origin`；白名单 `http://127.0.0.1:5175` 回显 ACAO + `Allow-Credentials: true`。
- 弱口令拦截：注册密码 `123` → 400「密码需为 8-32 位，且同时包含字母和数字」。
- 登录限流：连续失败 8 次后 → 429「登录尝试过于频繁，请稍后再试」。

### 2. 安全契约集成测试（新增）
`SecurityContractIntegrationTest`（@AutoConfigureMockMvc + 白名单测试属性），4 个用例：
- 公开接口五项安全头存在；
- 未知来源不泄露 ACAO（安全不变量断言，不绑定状态码）；
- 白名单来源回显 ACAO + 允许凭据；
- 白名单预检 OPTIONS 通过且 Allow-Methods 含 POST。

### 3. 退款并发测试时序修正
`RefundConcurrencyIntegrationTest.concurrentRefundsCreateOneRefundAndRevokeEntitlementOnce`：
- 修正过强的时序前提（原断言要求所有并发调用都成功），改为「至少一笔成功 + 任何失败必须是合法状态守卫拒绝」。
- 安全不变量完整保留：`t_refund` 恰好 1 笔、权益恰好回收 1 次（REVOKED）、订单终态 REFUNDED。
- 根因是 CI CPU 争用下赢家先提交终态、晚到线程被合法拒绝，非业务缺陷，非放宽断言掩盖缺陷。

### 4. 部署持久化缺口修复
- `compose.yml`：新增 `material-data` 命名卷挂载 `/app/data/materials`，环境变量 `MATERIAL_STORAGE_ROOT=/app/data/materials`，修复容器重建丢失已上传 PDF。
- `server/Dockerfile`：预创建 `/app/data/materials` 并 `chown app`（命名卷挂载点属主）。
- `.env.docker.example`：注明资料 PDF 持久化于 material-data 卷，COS 为遗留视频可选。

### 5. 生产配置审查 + 部署验收清单
- 复核 `application-prod.yml`：DB/Redis/JWT/CORS/支付宝凭据均必填无默认；actuator 绑定 127.0.0.1、health 详情 never；登录保护开启；种子密码留空随机；mock 默认关闭。
- 新增 `docs/部署与验收清单-资料商城.md`：本地安全验证表、生产配置审查、部署产物清单、云端验收清单、已知边界。
