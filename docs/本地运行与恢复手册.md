# btry 本地运行与恢复手册

更新日期：2026-11-02

本手册用于本地开发、演示验收和故障恢复。当前是单机 Spring Boot + Vue + MySQL + Redis + COS 架构，视频始终由浏览器直连 COS，不经过应用服务器转发。

## 1. 端口与依赖

| 组件 | 地址 |
|---|---|
| 前端 | `http://127.0.0.1:5175` |
| 后端 | `http://127.0.0.1:8084` |
| Actuator | `http://127.0.0.1:9091` |
| MySQL | `127.0.0.1:3306` |
| Redis | `127.0.0.1:6379` |

本地需要：

- Java 17
- Maven 3.9+
- Node.js 18+
- MySQL 8
- Redis 5+
- 可用的 COS 读取凭据

前端开发代理把 `/api` 转发到 `8084`。生产环境由反向代理提供前端静态文件，不依赖 Vite。

## 2. 一键启动

在仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\start-local.ps1
```

脚本按顺序完成：

1. 检查 Redis，未监听时从 `F:\Redis` 启动；
2. 检查后端 `8084`，未启动时执行 `mvn -q spring-boot:run`；
3. 检查前端 `5175`，未启动时执行 `npm run dev`；
4. 等待端口可用，并等待 Actuator 返回 `UP`；
5. 把本次启动信息写入 `logs/start-local.state.json`。

脚本是幂等的：已经运行的服务会跳过，不会重复启动。现有服务不是由脚本启动时，也会被识别为“已监听”。

Redis 不在默认目录时：

```powershell
$env:REDIS_HOME = 'D:\redis'
powershell -NoProfile -ExecutionPolicy Bypass -File tools\start-local.ps1
```

也可以显式传入 `-RedisHome`。Redis 由外部服务托管时使用 `-SkipRedis`。

日志：

- `logs/backend.out.log`
- `logs/backend.err.log`
- `logs/frontend.out.log`
- `logs/frontend.err.log`
- `logs/redis.out.log`
- `logs/redis.err.log`

## 3. 停止

只停止前后端：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\stop-local.ps1
```

同时停止本机 Redis：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\stop-local.ps1 -IncludeRedis
```

停止脚本按监听端口找到进程，并校验进程类型；前端还要求命令行包含当前项目的 `web` 目录，避免误杀其他 Node 服务。默认不会停止 MySQL。

## 4. 健康检查与验收

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:9091/actuator/health
```

最低验收顺序：

1. 管理员登录，确认内容管理只显示正式系列；
2. 教师登录，确认工作台只显示本人系列；
3. 学员登录，确认学习空间只显示已分配且已发布的系列；
4. 进入系列播放页，确认视频列表、播放地址和断点续播可用；
5. 检查浏览器控制台没有未处理错误。

演示账号与当前验收数据见仓库根目录 `README.md`。测试产生的临时邀请、学习进度和临时系列应在验收后清理。

## 5. 数据库备份

先启动 MySQL，再执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\backup-mysql.ps1
```

默认连接：

- 数据库：`btry_edu`
- 主机：`127.0.0.1:3306`
- 用户：`root`
- 密码：`root`

可通过 `-Database`、`-DbHost`、`-Port`、`-User`、`-Password` 或对应环境变量覆盖。备份文件写入 `backups/`，文件名带时间戳。

建议在以下操作前额外备份：

- Flyway 迁移；
- 批量调整账号或系列；
- 手工清理数据；
- 生产发布。

## 6. 恢复与演练

恢复会覆盖目标库，必须显式传入 `-Force`。生产或重要数据先停止后端写入。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\restore-mysql.ps1 `
  -BackupFile "backups\btry_edu-20261102-193800.sql" `
  -Database btry_edu `
  -Force
```

更安全的演练方式是恢复到临时库：

```powershell
mysql -uroot -proot -e "CREATE DATABASE btry_edu_restore_check CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
powershell -NoProfile -ExecutionPolicy Bypass -File tools\restore-mysql.ps1 `
  -BackupFile "backups\btry_edu-20261102-193800.sql" `
  -Database btry_edu_restore_check `
  -Force
```

恢复后至少核对：

- 账号数量与角色；
- 系列、章节、视频数量；
- 学员系列分配关系；
- `flyway_schema_history` 最新版本；
- 管理员登录、学习空间和播放地址。

确认后删除临时库。不要把“备份文件存在”当成“恢复可用”，至少定期做一次临时库恢复演练。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| Redis 启动失败 | 检查 `logs/redis.err.log`，确认 6379 未被占用、配置文件路径正确 |
| 后端端口已占用但健康检查失败 | 查看 `logs/backend.err.log`；必要时先执行停止脚本 |
| 前端页面打开但接口 502 | 确认后端 `8084` 已监听，Vite 代理配置未改动 |
| Actuator 不是 `UP` | 查看 `db`、`redis` 组件状态，再检查应用日志中的 `traceId` |
| 登录被限流 | 等待限流窗口结束；不要通过清空 Redis 绕过生产保护 |
| 视频能取地址但不能播放 | 检查 COS CORS、预签名 URL 时效、对象键和浏览器 Network |
| 恢复后版本不一致 | 核对备份时间、`flyway_schema_history` 和当前代码版本 |

## 8. 当前边界

- 视频不经过应用服务器，不使用 CDN、HLS。
- 本地脚本只负责开发运行，不替代生产进程守护。
- 默认不管理 MySQL 生命周期。
- 真实 10～40 分钟长视频验证保留到内容替换后的最终验收。
- 收费、评论、评分、完整 RBAC 不在当前 v1 范围。
