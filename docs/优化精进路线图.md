# 优化精进路线图（服务器直连开发）

## 0. 目标与约束

- 目标：在 `/opt/etry` 直接开发、测试、构建、部署，按 P0–P3 把项目提升到「可面试演示的生产级标准」，并留存全部证据。
- 约束：
  - 本地不再运行；服务器是唯一开发/运行环境。
  - 生产在线：Docker MySQL/Redis/backend + 宿主 nginx；4C/3.7G；资料 PDF 在 `btry_material-data` 卷；每日备份到 COS。
  - 任何变更：低峰执行、先备份、可回滚、有证据。
- 原则：证据优先；一次只动一个风险面；不为了关键词堆中间件。

## 1. 服务器开发工作流

### 1.1 源码与版本
- 源码：`/opt/etry`（含 git 历史）。
- 服务器直接编辑；提交前先跑 `tools/server-dev-test.sh unit`。
- 推送到 GitHub 需要一次凭据配置（部署密钥/PAT）；未配置时仅保留本地提交。CI 仍以 GitHub Actions 为门禁。

### 1.2 测试环境（与生产隔离）
- 测试库：容器 MySQL 内独立 schema `btry_it`（`tools/server-setup-test-db.sh` 一次性创建/授权）。
- 测试 Redis：同一 Redis 容器的 DB 15。
- Maven 容器：`maven:3.9.9-eclipse-temurin-17`，`--network host`，内存上限 1.2G，m2 缓存卷 `btry-m2`，国内镜像 `server/docker/maven-settings.xml`。
- 脚本：`tools/server-dev-test.sh [unit|it|all]`；启动前检查可用内存 <900MB 则中止，避免影响线上。
- 前端：node 容器 `npm ci && npm run build -- --base=/learn/`（部署脚本已内置）。

### 1.3 部署
- `bash /opt/etry/deploy-server.sh`：构建后端镜像 → 构建前端 → 原子切换 `learn` → 更新容器 → 容器内 readiness。
- 部署前：`docker exec` 备份 MySQL + 资料卷（已有每日 timer）；低峰执行。
- 回滚：`learn.prev-*`、`btry-backend:prev-*`、数据库备份。

### 1.4 证据目录
- `docs/evidence/<日期>/`：压测报告、支付/退款流水、告警截图、故障演练、恢复 RTO/RPO。

## 2. P0-0 服务器开发环境（当前）

- 创建 `btry_it` schema 并授权 `btry`。
- 落地 `server-setup-test-db.sh`、`server-dev-test.sh`。
- 验收：服务器上单测 240 通过；定向集成（安全契约 + 参数错误 + 订单列表）通过；线上容器健康不受影响。

## 3. P0 真实性与证据

1. 真实支付宝：沙箱或 ¥0.01（二选一，需确认）；覆盖下单→通知→履约→退款→对账，以及重复通知/金额篡改/超时查单。
2. 备份恢复演练：COS → 临时库 `btry_restore` → 校验 Flyway/关键表/PDF；记录 RPO/RTO。
3. k6：50/100/200 VU 打目录、登录、试读、下单；记录 TPS、P95/P99、错误率、CPU/内存/DB 连接。
4. 可观测：支付成功率、已付未履约、outbox 积压/DEAD、退款重试、5xx、DB 连接、JVM；webhook 告警；一次故障演练。
5. 安全遗留：依赖扫描、JWT 轮换演示、遗留教师端点清单、静态站安全头。

## 4. P1 交易内核加固

- `pay()`：订单/attempt 事务内落库，渠道调用移出事务；回调幂等测试。
- outbox：SKIP LOCKED、租约续期、批量上限、DEAD 重放/管理入口；双 relay 验证。
- 退款：租约心跳、渠道主动查单、未知状态处理；对账差异唯一键。
- 多实例：2 后端 + nginx；JWT 无状态、Redis 共享、无重复资金副作用。
- 调优：JVM/MySQL/连接池/慢查询；容量结论。

## 5. P2 中间件深度

- 生产：RabbitMQ（内存受限），订单超时/审计事件；outbox 保持可靠源，relay→MQ；幂等消费、手动 ACK、DLX/DLQ、积压监控。
- staging：RocketMQ（小堆）事务/延迟/顺序/DLQ 实验与集成测试。
- Redis：Redisson 锁/限流、目录缓存、穿透/雪崩、热 key。
- ES（可选）：SearchPort 抽象 + staging 单节点；生产保留 MySQL ngram 兜底。
- 不引入：Nacos/Dubbo/K8s/Seata（K8s 只做 manifests + CI 校验；定时任务多实例用 ShedLock）。

## 6. P3 前端/交付/面试

- `/me` 返回 roles+perms；前端按权限点门控；退役/迁移遗留教师端点。
- Playwright E2E：注册→试读→购物车→支付→书架→退款→客服审批。
- CI：构建产物、Trivy、依赖扫描、部署审批、回滚 job；compose/部署脚本校验。
- 文档：ADR、runbook、演示脚本、模拟面试与证据包。

## 8. 风险与回滚

- 内存：构建/测试限 1.2G，可用 <900MB 中止；低峰执行。
- 数据库：迁移前备份；测试只用 `btry_it`/`btry_restore`，不碰生产。
- 部署：前端/镜像/DB 三层回滚；变更后 15 分钟观察。
- 中间件：RabbitMQ/RocketMQ 先在 staging/本地验证，生产上线需单独评审。
