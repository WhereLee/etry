## 二、发现清单

### BLOCKER

**B1. 按仓库 compose 部署时 Mock 支付真实可用，可零成本获取资料权益**
- 证据：`compose.yml:69,80-81` 未设 `SPRING_PROFILES_ACTIVE`，`PAYMENT_PROVIDER` 默认 `mock`、`PAYMENT_MOCK_ENABLED` 默认 `true`；`PaymentSafetyGuard.java:26-29` 仅在 `prod` profile 下拒绝 Mock；`application-prod.yml:49-50` 的加固不生效。
- 影响：任何照 `compose.yml` 上线的环境，学员可走 Mock 收银台直接「支付成功」拿到权益。
- 建议（需决策，涉及部署口径）：compose 显式 `SPRING_PROFILES_ACTIVE=prod` 并补齐 prod 必填 env；或至少 `PAYMENT_PROVIDER=alipay` / `PAYMENT_MOCK_ENABLED=false`。CI 可加配置断言防回归。

### MAJOR

**M1. 运营订单列表：资料订单标题为空、按标题搜索失效**
- 证据：`AdminOrderMapper.xml:12-13` 只取 `o.series_title_snapshot AS seriesTitle`，`:35` 过滤同样只搜 `series_title_snapshot`；购物车多商品订单写的是 `product_title_snapshot`（`OrderRepository.java:103-111`），`series_*` 列为空。
- 影响：运营查单看到空白商品名，关键词搜不到资料订单一——阶段6验收漏网。
- 建议：`columns` 与 `filters` 改用 `COALESCE(o.product_title_snapshot, o.series_title_snapshot)`。

**M2. X-Forwarded-For 可伪造，绕过登录 IP 限流**
- 证据：`web/nginx.conf:18` 用 `$proxy_add_x_forwarded_for`（追加而非覆盖）+ `compose.yml:69` 信任转发头 + `ClientIpResolver.java:19,32-43` 取首个值。
- 影响：攻击者自带 `X-Forwarded-For` 轮换伪造 IP，429 限流形同虚设。
- 建议：nginx 改 `X-Forwarded-For $remote_addr`（`deploy/nginx-learn.conf:29` 已是正确写法）；或 resolver 仅取可信代理链末端。

**M3. 备份不含资料 PDF**
- 证据：`deploy/btry-backup.sh:21-25` 仅 `mysqldump`；`MATERIAL_STORAGE_ROOT`（`application.yml:67-68`）下的上传 PDF 未备份。
- 影响：恢复后运营上传的资料文件丢失（种子演示件会惰性重建，但真实上传件不可恢复）。
- 建议：备份脚本打包存储根目录，纳入恢复演练。

**M4. 遗留课程端点仅 legacy 角色守卫，RBAC 降权不生效**
- 证据：`AdminSeriesController.java:30/48/59`、`TeacherInvitationAdminController.java` 用 `@RequireRole("ADMIN")`；`AdminRbacService.assignRoles:38-49` 只改 RBAC 授予，不回写 `t_user.role`。
- 影响：收回某账号 SUPER_ADMIN 后，其仍可改系列上下架/发教师邀请。属 README 已列的遗留债，但仍是真实授权不一致。
- 建议：迁移到 `@PreAuthorize` 权限点，或直接退役遗留端点。

### MINOR

**m1. 参数校验类异常回落 500**
- 证据：`GlobalExceptionHandler.java` 仅处理 `MethodArgumentNotValidException`，缺 `HandlerMethodValidationException`（如 `MaterialCatalogController.java:47` 空 keyword）、`MethodArgumentTypeMismatch`、`HttpMessageNotReadable` → 走兜底 500。
- 建议：补 400 映射。

**m2. 生产暴露 API 文档**
- 证据：`application-prod.yml` 未禁 springdoc；`application.yml:37-41` 默认开启；`SecurityConfig.java:48` `anyRequest().permitAll()`。
- 建议：prod 关 `api-docs`/`swagger-ui`。

**m3. 订单列表 N+1**
- 证据：`OrderService.java:124-127` → `view()` → `owned():191-198`，每单再查明细+权益。
- 建议：批量查询订单明细与权益。

**m4. 订单退款查询缺索引**
- 证据：`PaymentRepository` 按 `order_id` 查退款；`V15` 删除 `uk_refund_order`，`V20` 仅覆盖部分。
- 建议：补 `idx_refund_order` 迁移。

**m5. 文档小错**
- `README.md:18`「自助注册/首次强制改密」与 `AuthService.java:45-57` 注册免改密矛盾（种子账号才强制改密）。
- `docs/演示脚本-资料商城.md` 按钮名「确认支付」实为「模拟支付成功」（`MockCashier.vue:92`）、「申请退款」实为「申请整单退款」（`OrderDetail.vue:227`）。

**m6. 配置一致性**
- `.env.docker.example:20` `REDIS_DATABASE` 未被 compose 透传（无效变量）。
- `.env.docker.example:12-13` 端口示例与 `docs/Docker运行与云服务器验证.md` 的 18084/19091 冲突。
- `deploy/setup-server.sh` 未安装 Java/MySQL/Redis/Caddy，与部署清单描述不符。

## 三、亮点（已核验）

- 鉴权矩阵：运营端点全部 `@PreAuthorize` 权限点；公开白名单仅 6 条 + GET `/api/materials/**`；下载另校权益。
- JWT：签名/过期/tokenVersion/每请求从库加载权限/首改密 428/非法 401。
- 注入与文件：无 `${}`、无拼接注入；上传 `%PDF` 魔数 + 路径越界 + 服务端文件名；试读截页 + 购买者水印。
- 支付验签：AlipayNotify 验签 + app_id/seller 校验 + 64KB 限制。
- 交易内核：唯一退款行 + 条件认领 + 租约 token 防覆盖 + 事务性 outbox；订单 clientRequestId 唯一 + 事件唯一 `INSERT IGNORE`；权益 upsert 只撤 ACTIVE 且 `source_order_id` 精确；对账幂等唯一约束；无破坏性迁移；全链路 long 分。
- 工程卫生：0 TODO/FIXME；`.gitignore` 覆盖 target/node_modules/logs/data/.env；Dockerfile 多阶段非 root；prod yml 必填无默认。

## 四、结论与建议顺序

交付质量整体达标，**无资金/数据安全的内核缺陷**；主要问题是「上线口径」而非内核：

1. 发布前必须定夺 B1（compose 部署口径）——需业务/运维决策。
2. 发布前修复 M1、M2、M3（均为小改动、影响面明确）。
3. 遗留债 M4 随课程模块退役处理。
4. MINOR 可排入下个迭代。
